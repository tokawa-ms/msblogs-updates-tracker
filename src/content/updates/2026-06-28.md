#### [The performance dividend: Optimizing PostgreSQL on Azure directly in Visual Studio Code](https://azure.microsoft.com/en-us/blog/the-performance-dividend-optimizing-postgresql-on-azure-directly-in-visual-studio-code/)
- 公開日時: 2026-06-26T17:00:00.000Z
- 要約: Visual Studio Code向けのPostgreSQL拡張機能に、Azure上のPostgreSQL運用をそのままエディター内で可視化・診断・最適化しやすくする性能強化が加わった。新たにサーバーメトリクスのダッシュボード、Azure Advisorの推奨事項表示、改良されたクエリプラン可視化とAI支援分析が統合され、クエリ作成時のIntelliSenseや大規模DB向けのオブジェクトエクスプローラー信頼性も改善された。あわせてAzure HorizonDBはパブリックプレビューとして紹介されているが、現時点で多くの本番用途にはAzure Database for PostgreSQLが推奨される。
- なぜ重要か: Azure上でPostgreSQLを運用するエンタープライズの開発者、DBA、プラットフォーム担当者にとって、診断・監視・チューニングをVS Codeに集約できる点が重要だ。記事では、複数ツール間の切り替えで失われていた文脈を減らし、問題検知から調査までの時間を短縮できること、さらにPostgreSQL専門家でない開発者でも高い性能要件に対応しやすくなることが示されている。AIネイティブ構成を検討するチームにはHorizonDBという選択肢も示されたが、本番の主軸は引き続きAzure Database for PostgreSQLだ。

**重要ポイント**
- VS Code内のサーバーメトリクスダッシュボードで、CPU、メモリ、ストレージ、接続数などの主要指標を確認でき、Azure固有のテレメトリと履歴インサイトも参照できる。
- Azure Advisorの推奨事項がエディターに直接表示され、Azureテレメトリに基づく構成、インデックス、リソース最適化の提案を実ワークロードに即して受けられる。
- クエリプラン可視化が改善され、AI支援のクエリ分析と最適化もワークフローに統合されたため、VS Codeを離れずにボトルネック把握と改善案検討を進めやすい。
- 開発体験ではschema-aware IntelliSense、search\_path-aware query authoring、複雑で大規模なDB向けの安定したobject explorerが強化され、Microsoft Entra ID認証とAzureリソース検出も統合されている。
- Azure HorizonDBはAI対応のPostgreSQL互換ワークロード向けとしてパブリックプレビューで紹介される一方、現時点では大半の本番ワークロードにAzure Database for PostgreSQLが推奨されている。

<details><summary>English summary</summary>

The PostgreSQL extension for Visual Studio Code has been enhanced to make performance monitoring, diagnosis, and tuning for PostgreSQL on Azure easier directly inside the editor. It now brings in a server metrics dashboard, Azure Advisor recommendations, improved query plan visualization, and AI-assisted analysis, while also improving authoring features and large-database usability. Azure HorizonDB is also mentioned as a public preview option, but Azure Database for PostgreSQL remains the recommended choice for most production workloads today.

</details>

#### [From insight to action: The next phase of agentic cloud operations](https://azure.microsoft.com/en-us/blog/from-insight-to-action-the-next-phase-of-agentic-cloud-operations/)
- 公開日時: 2026-06-23T15:45:00.000Z
- 要約: Azure Copilot observability agentが一般提供となり、Azureでは環境全体のテレメトリーを継続分析して、障害の兆候把握から調査支援までを日常運用に取り込めるようになった。あわせてAzure Resource Manager MCP Serverがパブリックプレビューとなり、コストと使用量のデータをAIエージェントや開発ツールへ標準的に接続できるようにしている。記事は、観測、ガバナンス、最適化を人間が関与するポリシー付きの閉ループ運用として結び付ける構想を示している。
- なぜ重要か: ハイブリッド基盤、マイクロサービス、AIワークロードを運用する開発者、IT、運用チームに関わる内容で、手作業では追い切れなくなったテレメトリーやアラート、変動しやすいコスト利用を、ポリシーとアクセス制御付きのエージェントで扱えるようにする点が重要だ。とくに、開発者はコスト影響を意識しながら構築でき、運用チームは自然言語で調査と最適化を進められるため、障害対応と最適化が同じ運用ループに統合される。

**重要ポイント**
- Azure Copilot observability agentは、アプリケーショントポロジー、依存関係、ベースライン挙動を含む環境全体のテレメトリーを継続分析し、問題の兆候が出た段階でパターン検出と調査開始を支援する。
- インシデント対応では、関連シグナルの自動グルーピングやサービス間依存関係の追跡によりノイズ削減と根本原因の絞り込みを進め、判断に必要な文脈付き提案を提供するとしている。
- 導入効果の例として記事は、観測エージェントによりインシデント解決の高速化と運用負荷の削減が進み、月あたり推定250時間のエンジニアリング時間を取り戻したという利用者の声を紹介している。
- 最適化では、Microsoftはコスト、性能、レジリエンス、サステナビリティを継続改善する実践と定義し、AIによる変動の大きい利用パターンのため、定期レビュー中心の従来型コスト管理だけでは対応しにくいと説明している。
- Azure Resource Manager MCP Serverのパブリックプレビューでは、AIエージェントが標準化インターフェース経由でコスト・使用量データへアクセスでき、カスタム統合なしで開発環境、copilot、独自ワークフローにその知見を持ち込める。

<details><summary>English summary</summary>

Azure Copilot observability agent is now generally available, bringing continuous telemetry analysis and assisted investigation into day-to-day Azure operations. Microsoft is also putting the Azure Resource Manager MCP Server into public preview so cost and usage data can flow into AI agents and developer tools. Together, the article frames observability, governance, and optimization as a human-governed closed-loop operating model.

</details>
