#### [Deep dive into Azure Maia 300 architecture](https://azure.microsoft.com/en-us/blog/deep-dive-into-azure-maia-300-architecture/)
- 公開日時: 2026-10-12T13:00:00.000Z
- 要約: Azure Maia 300は、LLM推論向けにソフトウェア、シリコン、ラック、ネットワーク、データセンターまでを一体設計した第3世代アーキテクチャとして、Maia 200からメモリ構成とスケールを大きく拡張した。チップレット間NUMA化、低精度形式の強化、96基/ラックと最大12,288基のsuperpod対応により、Microsoftはラック当たりトークン処理性能が最大7倍、性能/ワットが2.5倍超になったと説明している。狙いは、長文脈やマルチステップ実行、ツール利用を含むエージェント型推論を、電力と冷却の制約内でより効率よく支えることにある。
- なぜ重要か: 影響を受けるのは、Microsoft Copilot、GitHub Copilot、Microsoft Foundryのような大規模AIサービスを使う顧客と、それらを運用するMicrosoftだ。記事では、長いコンテキストやマルチステップ実行、ツール利用を伴うエージェント型推論に合わせて、固定された電力・冷却枠の中でメモリ帯域、並列度、推論性能を伸ばし、これらの製品群へより多くの容量と性能を回せる点に意味があると位置付けている。

**重要ポイント**
- Maia 300は、SoCメモリをUMAからチップレット横断のNUMAへ変更し、計算の近くにデータを置けるようにした。さらにラックは96基へ倍増し、スケールアップ領域は最大12,288基のsuperpodまで拡大した。
- メモリ階層では8基のHBM4を搭載し、アクセラレータ当たり288GB容量と18TB/s帯域を持つ。Microsoftによれば、Maia 200比でメモリ帯域は2.5倍、容量は33%増、HBM帯域/ワットは約2倍になった。
- ネットワークはEthernetベースの2層構成で、pod内からsuperpod全体まで同じ通信モデルを使う。条件付きでsuperpod内の相手へ最大750GB/sを出せ、prefillとdecodeのワーカーを独立に配置できるため、ジョブ配置の柔軟性を高めている。
- ラック設計では167kWラックに24基の4アクセラレータトレイ、計96基を収容し、Maia 200比でアクセラレータ密度を倍増した。冷却は液冷がラック熱負荷の80%以上を処理し、記事ではラック全体で性能/ワットを最大2.5倍に高めたとしている。

<details><summary>English summary</summary>

Azure Maia 300 is a third-generation architecture co-designed across software, silicon, racks, networking, and datacenters for LLM inference, with major expansions over Maia 200 in memory organization and scale. With chiplet-level NUMA, enhanced low-precision formats, support for 96 accelerators per rack and up to 12,288 per superpod, Microsoft says it delivers up to 7x rack-scale token throughput and more than 2.5x performance per watt. Its goal is to support long-context, multi-step, tool-using agentic inference more efficiently within power and cooling limits.

**Why it matters:** The main beneficiaries are customers using large-scale AI services such as Microsoft Copilot, GitHub Copilot, and Microsoft Foundry, as well as Microsoft operating those services. The article frames the significance as improving memory bandwidth, parallelism, and inference performance for long-context, multi-step, tool-using agentic workloads while staying within fixed datacenter power and cooling limits, allowing more capacity and performance to be delivered to those product lines.

**Key points**
- Maia 300 changes SoC memory from UMA to chiplet-spanning NUMA so data can be placed near the compute that uses it. It also doubles the rack to 96 accelerators and expands the scale-up domain to a superpod of up to 12,288 accelerators.
- Its memory hierarchy uses eight HBM4 stacks, providing 288 GB of capacity and 18 TB/s of bandwidth per accelerator. Microsoft says that versus Maia 200 this gives 2.5x memory bandwidth, 33% more capacity, and about 2x HBM bandwidth per watt.
- The network uses a two-tier Ethernet-based design with one communication model from pod to superpod. Under certain conditions an accelerator can deliver up to 750 GB/s to a peer within the superpod, and prefill and decode workers can be placed independently for more flexible job placement.
- At the rack level, it fits 96 accelerators in a 167 kW rack using 24 four-accelerator trays, doubling accelerator density versus Maia 200. Liquid cooling handles more than 80% of rack thermal load, and the article says the rack design delivers up to 2.5x better performance per watt.

</details>

#### [GitHub Copilot app for Beginners: How to teach Copilot about your codebase](https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-how-to-teach-copilot-about-your-codebase/)
- 公開日時: 2026-10-12T17:43:59.000Z
- 要約: GitHub Copilot appでコードベース固有の文脈を教える方法として、記事はカスタム指示、エージェントスキル、カスタムエージェント、MCPサーバーの4つを整理している。リポジトリ全体や特定パス向けの指示を .github 配下に置き、手順化できる作業はスキルとしてまとめることで、Copilotが毎回推測せず既存の規約や手順に沿って動けるようにする。さらに、広範な作業向けの専用エージェントや、Playwrightのような外部ツール接続を組み合わせることで、リポジトリ外の情報やブラウザー操作まで活用できる。
- なぜ重要か: この内容は、毎回同じ規約や手順を説明している開発者やチームに関係する。記事の要点は、そうした知識をリポジトリ内の指示、スキル、エージェント定義として置くことで、Copilotがプロジェクト固有のやり方を継続的に参照し、必要に応じて外部ツールまで使えるようにする点にある。

**重要ポイント**
- リポジトリ共通の規約は .github/copilot-instructions.md に置き、アーキテクチャ、命名規則、テストや検証の期待値などを定義できる。さらに .github/instructions 配下では applyTo フィールド付きのパス別指示を作れ、該当ファイルでは全体向けと個別向けの両方をCopilotが参照できる。
- 反復的な手順は .github/skills の各サブフォルダーにスキルとして置ける。SKILL.md には、いつ使うか、どのスクリプトでテストやlintを回すか、何を確認するか、よくある失敗の切り分け方まで書けるため、Copilotはコマンドを推測せず既存プロセスに従える。
- 複数ファイルにまたがる専門的な作業には、.github/agents に置くカスタムエージェントを使う。用途、指示、利用ツール、関連するプロジェクト文脈を定義でき、アクセシビリティレビューのような単一手順では収まらない継続的な役割に向く。
- MCPサーバーを接続すると、Copilotはリポジトリ外のツールやデータにもアクセスできる。例としてPlaywrightを設定すれば、ブラウザーでアプリを開いて手動テストのように操作でき、自動チェック通過だけでなく更新後の画面挙動も確認できる。

<details><summary>English summary</summary>

For the GitHub Copilot app, the article explains four ways to teach it about a codebase: custom instructions, agent skills, custom agents, and MCP servers. By storing repository-wide and path-specific guidance under .github and packaging repeatable procedures as skills, teams can let Copilot follow existing conventions and workflows instead of guessing each time. It also shows how dedicated agents for broader tasks and external-tool connections such as Playwright can extend Copilot beyond the repository to browser-based verification and other outside context.

**Why it matters:** This matters to developers and teams who keep repeating the same conventions and procedures to Copilot. The article’s core point is that by storing that knowledge in repository instructions, skills, and agent definitions, Copilot can consistently use project-specific practices and, when needed, reach external tools as well.

**Key points**
- Repository-wide conventions can be stored in .github/copilot-instructions.md, covering architecture, naming, and testing expectations. Path-specific files under .github/instructions can use an applyTo field, and Copilot can use both the repository-wide and file-specific guidance on matching files.
- Repeatable procedures can be packaged as skills under .github/skills, with one subfolder per skill. A SKILL.md file can describe when to use it, which scripts run tests and linting, what those scripts check, and how to troubleshoot common failures, so Copilot follows the established process instead of guessing commands.
- For broader specialized work across multiple files, custom agents can be defined under .github/agents. They can specify purpose, instructions, tools, and relevant project context, making them suitable for recurring roles such as accessibility reviews that go beyond a single procedure.
- By connecting MCP servers, Copilot can access tools and data outside the repository. With Playwright configured, for example, it can open the app in a browser and interact with it for manual-style testing, helping verify interface behavior in addition to automated checks.

</details>

Microsoft has added three capabilities—Home, Code, and Autopilot—to the Copilot app, unifying chat, delegated work, app creation, and persistent agents in one experience. In Home, users can work with Word, Excel, and PowerPoint directly, while Code uses the same underlying technology as GitHub Copilot to build solutions from natural language. Home and Code are rolling out through the Frontier program, and Autopilot expands to private preview at the end of the month.

**Why it matters:** For Microsoft 365 knowledge workers, this makes it easier to move across document creation, delegated tasks, lightweight app building, and autonomous execution within Copilot, linking conversations more directly to real files and real work. Non-developers are especially affected because Code lowers the barrier to building small solutions, while IT teams get tenant-hosted execution, centralized plugin approval, and spending policy controls to support broader rollout with governance.

**Key points**
- Home brings Chat and Cowork together in one place, and Office in Copilot lets users create and update real Word, Excel, and PowerPoint files directly from Copilot.
- Code can generate apps, trackers, dashboards, and automations from natural language, runs in a sandboxed environment, and can be hosted securely within the tenant. It starts rolling out to Frontier at the end of the month, reaches broad availability in the following weeks, and is planned for preview later this year for Microsoft 365 Premium and Pro subscribers.
- Autopilot, formerly Scout, is a cloud-hosted personal agent that can continue recurring work and follow-ups without waiting for prompts. It has its own identity, memory, computer, and workspace inside the tenant, and its private preview expands at the end of the month.
- On pricing, Chat and apps like Word, Excel, and PowerPoint stay under the fixed-cost USL, while Cowork, Code, Autopilot, and frontier models use usage-based billing. FinOps for AI also expands spend management to cover Code and Copilot Managed Runtime.
