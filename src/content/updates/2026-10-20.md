#### [How to continue a GitHub Copilot app session in VS Code](https://github.blog/ai-and-ml/github-copilot/how-to-continue-a-github-copilot-app-session-in-vs-code/)
- 公開日時: 2026-10-19T18:47:22.000Z
- 要約: GitHub Copilotアプリのセッションは、会話やコード変更、作業コンテキストを保ったままVS Codeで開いて継続できる。セッションに紐づく同じworktreeで差分を確認し、手作業で編集・ローカル検証した後、関連PRを追跡するブランチへ変更をpushする手順を解説している。新しいエディターで作業を再構成する必要はない。
- なぜ重要か: エージェントに大枠の実装を任せた開発者は、会話や作業履歴を引き継いだままVS Codeで細部を確認し、手作業の修正やローカルテストに移れる。作業やPRを作り直さずに編集者へ移行できるため、エージェントの変更を自分でレビューして仕上げる流れをつなげられる。

**重要ポイント**
- セッションから「Open in VS Code」を選ぶと、セッション用worktreeでプロジェクトが開き、既存セッションもCopilotサイドバーに表示される。複数のエディターやVS Code環境が提示された場合は利用するものを選ぶ。
- 編集前にSource Controlビューで変更ファイルを確認し、差分を行単位でレビューする。実装の妥当性、リポジトリ規約、エッジケース、テスト、無関係な変更の有無を点検する。
- VS Code上で既存worktreeのファイルを直接編集でき、統合ターミナルからリポジトリに応じた検証を実行する。例としてnpm install、npm test、npm run lint、npm run devが挙げられている。
- 仕上げに差分を再確認してコミット・pushすると、セッションに関連付けられたブランチの更新が既存のプルリクエストに反映される。別のチェックアウトへのファイルコピーやPRとの手動再接続は不要。

<details><summary>English summary</summary>

A GitHub Copilot app session can be opened in VS Code with its conversation, code changes, and working context intact. The tutorial explains how to review the diff in the session’s worktree, edit and test locally, then push the changes on the branch that tracks the associated pull request without reconstructing the work in a new editor.

**Why it matters:** Developers who delegate the bulk of an implementation can move to VS Code for detailed review, hands-on edits, and local testing while retaining the conversation and work history. This connects the editor workflow to the existing work and pull request, so there is no need to recreate the task or reconnect the changes.

**Key points**
- Choose Open in VS Code from the session to open the project in its worktree and show the existing session in the Copilot sidebar; choose an editor or VS Code installation if more than one is offered.
- Before editing, use the Source Control view to inspect changed files and review the diff line by line, checking the implementation, repository conventions, edge cases, tests, and unrelated changes.
- Edit files directly in the existing worktree and run the repository’s validation workflow in the integrated terminal. Examples include npm install, npm test, npm run lint, and npm run dev.
- Review the final diff, commit, and push; updating the session-associated branch updates the pull request already tracking the work, without copying files to another checkout or reconnecting the PR manually.

</details>

### Microsoft 365 Blog (1)

#### [Introducing the new Copilot with Home, Code and Autopilot](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- 公開日時: 2026-09-25T12:07:25.000Z
- 要約: Microsoft Copilotは、ChatやCoworkをまとめるHome、自然言語から業務用ソリューションを作るCode、指示後も継続して動くAutopilotを備える新しい体験へ刷新される。Word、Excel、PowerPointの編集機能や企業データとの連携、AI利用費を管理する機能も拡充される。提供はFrontierでの段階的な展開やプレビューが中心で、機能ごとに時期と提供状況が異なる。
- なぜ重要か: 個人ユーザーは会話、委任、業務ツールの作成をCopilot内で行い、チームは共同編集や継続稼働するエージェントを活用できる。企業の管理者はデータ連携や権限管理に加え、利用モデルやAI支出を制御できる一方、機能によって一般提供・プレビュー・段階展開が分かれているため、利用可否は各機能の提供状況に左右される。

**重要ポイント**
- HomeではChatとCoworkを一か所で利用でき、Office in CopilotによりWord、Excel、PowerPointの編集可能な文書・ブック・プレゼンテーションを会話と並行して作成・更新できる。チームの編集内容も同期される。
- Codeは自然言語でアプリや自動化などを作成し、サンドボックスで実行してテナント内に安全にホストできる。Frontierには9月末に展開開始、幅広い提供は数週間以内、Microsoft 365 PremiumとProの加入者向けプレビューは年内予定。Copilot Managed Runtimeもプレビュー中。
- Autopilot（旧称Scout）は、名前・役割・目標を設定すると、スレッドのフォローや定期業務などを継続して実行するクラウドホスト型エージェント。テナント内の独自IDや権限・監査・ガバナンスを備え、9月末にプライベートプレビューを拡大する。
- Fabric IQのPower BIセマンティックモデルを使ったChatとCoworkのグラウンディングは一般提供中。Dynamics 365とPower Platformのデータ・ワークフロー連携は翌月にパブリックプレビューとして展開予定で、プラグインの統合カタログは現在展開中、数週間以内に各サーフェスで一般提供予定。
- 日常利用向けのユーザーサブスクリプションライセンス（USL）は固定費で、モデル選択やCopilot機能を含む一方、Cowork、Code、Autopilotなどのエージェント型機能と先端モデルは従量課金（UBB）で動作する。管理者には支出ポリシー、クレジット申請、利用可能モデルの設定機能が提供される。

<details><summary>English summary</summary>

Microsoft Copilot is being refreshed with Home, which brings Chat and Cowork together; Code, which builds work solutions from natural-language requests; and Autopilot, which continues working after receiving instructions. The update also expands Word, Excel, and PowerPoint editing, enterprise-data integration, and tools for managing AI spending. Rollout is staged through Frontier and previews, with availability varying by capability.

**Why it matters:** Individuals can use Copilot for conversation, delegated work, and building work tools, while teams can use collaborative editing and agents that keep working. Enterprise admins can manage data connections and permissions as well as control models and AI spending. Because capabilities have different general-availability, preview, and staged-rollout statuses, access depends on each feature’s availability.

**Key points**
- Home brings Chat and Cowork together, while Office in Copilot lets users create and update editable Word, Excel, and PowerPoint files alongside their conversation, with team edits synchronized.
- Code builds apps and automations from natural language and can run in a sandbox and be hosted securely within a tenant. It starts rolling out to Frontier at the end of September, with broader availability in the coming weeks and a preview for Microsoft 365 Premium and Pro subscribers later in the year. Copilot Managed Runtime is also in preview.
- Autopilot, formerly Scout, is a cloud-hosted agent that can continue tasks such as following up on threads and running recurring work after being given a name, role, and goal. It has its own identity within a tenant and is expanding to private preview at the end of September.
- Chat and Cowork grounding with Fabric IQ and Power BI semantic models is generally available. Dynamics 365 and Power Platform data and workflow integration is planned for public preview over the next month, while a unified plugin registry is rolling out now and expected to be generally available across surfaces in the coming weeks.
- The user subscription license (USL) covers everyday use at a fixed cost and includes model selection and Copilot capabilities, while agentic features such as Cowork, Code, and Autopilot and frontier models use usage-based billing (UBB). Admins can manage spending policies, credit requests, and available models.

</details>

### Microsoft Fabric Blog (1)

#### [Fabric Data Warehouse integration with Fabric User Data Functions (Preview)](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Fabric-Data-Warehouse-integration-with-Fabric-User-Data/ba-p/5375137)
- 公開日時: 2026-10-19T21:00:00.000Z
- 要約: Fabric Data WarehouseがFabric User Data Functionsとの連携をプレビューで提供し、T-SQLからPythonのカスタム関数を呼び出せるようになりました。外部関数はSELECT、INSERT、UPDATEなどで実行でき、メールやTeams通知、OneLakeや各種データソースへのアクセス、秘密情報の取得などに利用できます。記事では、IPv6アドレスからネットワークプレフィックスを計算して列に保存する例も紹介しています。
- なぜ重要か: T-SQLを中心に作業するデータウェアハウスのチームは、別のアプリケーションやパイプラインを構築せずにPythonの処理をクエリから利用できます。特に、複雑なIPv6プレフィックス計算の結果を保存すれば、後続クエリで計算を繰り返さずネットワーク範囲ごとにイベントを分析できます。この連携はプレビューとして案内されています。

**重要ポイント**
- Fabric Data WarehouseでT-SQL外部関数を作成し、Fabric User Data Functions項目内のPython関数を参照できます。呼び出し時にはUser Data Functionsランタイムに処理を委譲します。
- 用途として、API呼び出しやメール・Teams通知、Excel・XML・PDFの読み取り、OneLakeやFabricデータベース、Azure Cosmos DB、他ワークスペースのウェアハウスへのアクセスが挙げられています。
- Azure Key VaultまたはFabric variable librariesからシークレットや設定値を取得でき、暗号化・復号・マスキング、データの補強や検証、機械学習モデルによるスコアリングにも利用できます。
- IPv6の例では、Pythonのipaddress機能でアドレスとプレフィックス長からCIDR表記のネットワークを求め、T-SQLのUPDATEで各イベントの/48プレフィックスをNetworkPrefix列に保存します。

<details><summary>English summary</summary>

Fabric Data Warehouse has introduced a preview integration with Fabric User Data Functions, allowing T-SQL to invoke custom Python functions. External functions can run in statements such as SELECT, INSERT, and UPDATE and support tasks including notifications, data access, and retrieving secrets. The article also demonstrates calculating IPv6 network prefixes and storing them in a column.

**Why it matters:** Teams working primarily in T-SQL can use Python logic from warehouse queries without building separate applications or pipelines. In particular, storing the results of complex IPv6 prefix calculations lets downstream queries analyze events by network range without repeating the calculation. The integration is presented as a preview.

**Key points**
- In Fabric Data Warehouse, T-SQL external functions can reference Python functions in a Fabric User Data Functions item. Calls are delegated to the User Data Functions runtime.
- Use cases include calling APIs and sending email or Teams notifications, reading Excel, XML, and PDF files, and accessing OneLake, Fabric databases, Azure Cosmos DB, and warehouses across workspaces.
- The integration can retrieve secrets and configuration values from Azure Key Vault or Fabric variable libraries, and can support encryption, decryption, masking, data enrichment and validation, and machine-learning scoring.
- In the IPv6 example, Python's ipaddress functionality derives a CIDR network from an address and prefix length, and a T-SQL UPDATE stores each event's /48 prefix in the NetworkPrefix column.

</details>
