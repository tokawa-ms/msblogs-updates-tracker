#### [The harness is all you need (mostly)](https://github.blog/ai-and-ml/github-copilot/the-harness-is-all-you-need-mostly/)
- 公開日時: 2026-07-27T18:00:00.000Z
- 要約: GitHub Copilotの使い方として、CLIや新しいGitHub Copilot appなどで共通のharnessを軸に、プロトタイプ作成、/planでの設計、Autopilotでの実装、Rubber Duckレビューまでを一続きで進める実践的ワークフローが示された。奇抜なプロンプトや新しいAIツールを追い回すのではなく、既存機能だけで反復しながら品質を高めるのが主眼だ。
- なぜ重要か: AI関連の新ツールや手法の多さに圧倒されがちな開発者にとって、複雑な設定や“魔法のプロンプト”に頼らず、GitHub Copilotの既存機能だけで再現しやすい進め方を示している点が重要だ。シンプルさは並行作業や限られたコンテキスト管理にも向いており、多くの利用者が安定して高品質な結果を目指しやすくなる。

**重要ポイント**
- GitHub Copilot CLI、新しいGitHub Copilot app、VS Codeなどの体験は同じharnessに集約されつつあり、学習を始めるならUIが少なく直接的なCLIから入ることを勧めている。
- YOLO mode（Allow All）を有効にすると、エージェントは都度承認なしでコマンドを実行できる。一方で、安全のためローカルマシンではなく、GitHub Codespacesやdevelopment containersのようなサンドボックスで動かすことを勧めている。
- 実装前には低コストなプロトタイプで要件のニュアンスを可視化し、その後は同じセッションのまま/planでエッジケースを掘り下げる流れを推奨している。モデルはGPT 5.6 TerraやClaude Sonnetのような中規模モデルをmedium reasoningで使い、同じモデルと推論レベルを維持するとprompt cachingにより将来のリクエストが割引されると説明している。
- Autopilotは計画項目の完了確認まで含むbuilt-in loopとして実装を進め、必要に応じてExploreやGeneral Purposeのsubagentを自動で使い分ける。仕上げではRubber Duck reviewを別AIファミリーのモデルに依頼し、単一モデルでは見落としうる問題の発見を狙う。

<details><summary>English summary</summary>

For GitHub Copilot, the article presents a practical workflow built around the shared harness across the CLI, the new Copilot app, and other surfaces: prototype first, plan with /plan, implement with Autopilot, and finish with a Rubber Duck review. The emphasis is on using existing Copilot features to iterate toward quality instead of chasing new AI tools or fancy prompts.

</details>

#### [GitHub Copilot app for Beginners: Getting started](https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-getting-started/)
- 公開日時: 2026-07-27T16:00:00.000Z
- 要約: GitHub Copilot appの入門向けガイドでは、作業をプロジェクト起点のセッションとして始め、リポジトリ文脈付きで変更や検証を進める使い方が示された。加えて、Quick Chatで別スレッドを並行して進め、/create-canvasによるブラウザキャンバスでUIを確認しながら調整できる。変更後はAgent MergeでプルリクエストのレビューやCI対応を補助し、マージまでの流れを継続できる。
- なぜ重要か: 複数の開発タスクを行き来する開発者や、GitHub Copilot appを使い始める人にとって重要なのは、会話単位ではなくプロジェクト、並行セッション、UI確認、PR追跡までを一つの作業空間で扱える点だ。記事は、実装中の文脈維持、別件調査の並行実行、視覚的な調整、レビュー後対応までを分断せずに進める利用像を具体化している。

**重要ポイント**
- 作業はプロジェクトにひも付くエージェントセッションから始まり、GitHubまたはローカルマシンのプロジェクトを追加して、コードベースや必要なツールを含む状態で着手できる。セッションは関連ファイルの特定、変更、テスト実行まで支援する。
- Quick Chatを使うと、既存の作業を中断せずに別の質問や調査用セッションをホーム画面から追加でき、コードベース理解や方針検討を別スレッドで進められる。
- UI変更では/c​​reate-canvasスラッシュコマンドでブラウザキャンバスを開き、Enable Canvas Dev ModeとPick &amp; Polishを使って画面上の要素を直接選び、次の依頼の文脈として反映できる。
- Agent Mergeはプルリクエストに対して有効化でき、レビュー指摘への対応、CI失敗の支援、マージ競合への対処を行い、必要なチェック通過後にマージ判断へ進める。

<details><summary>English summary</summary>

The beginner guide to the GitHub Copilot app shows how to start work from project-linked sessions with repository context, use Quick Chat for parallel threads, refine UI changes in a browser canvas via /create-canvas, and keep pull requests moving through review and CI with Agent Merge.

</details>
