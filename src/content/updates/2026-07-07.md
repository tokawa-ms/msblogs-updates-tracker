### Microsoft Fabric Blog (1)

#### [Deep dive into tooltip options in Power BI visuals (Generally Available)](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Deep-dive-into-tooltip-options-in-Power-BI-visuals-Generally/ba-p/5255518)
- 公開日時: 2026-07-06T17:00:00.000Z
- 要約: Power BI visualsでは、ツールチップの新オプションであるTooltip fields onlyとSentence format onlyが一般提供になり、ホバー時に出す項目や文章をレポート作成者が細かく制御できるようになった。既定のツールチップに項目を足す方法から、表示項目の厳選、文テンプレート、レポートページによる完全置き換えまで段階的にカスタマイズできる。さらに、Help tooltipはデータ点ではなくビジュアル自体の説明用として通常のデータツールチップと併用できる。
- なぜ重要か: この変更は、Power BIのレポート作成者と閲覧者の双方に影響する。作成者は既定表示に縛られず、ホバー内容を必要な項目や自然文に絞り込める一方、閲覧者はデータ点から離れずに文脈や補足説明を得られる。さらに、レポートページ型ツールチップは表現力が高いが操作できないため、用途に応じて通常ツールチップ、ヘルプ、drillthroughを使い分ける判断材料になる。

**重要ポイント**
- Tooltip fields onlyを有効にすると、ビジュアルで使っている符号化フィールドは非表示になり、Tooltipフィールドウェルに入れた項目だけを表示できる。設定場所は Format visual &gt; General &gt; Tooltips &gt; Options で、ホバー表示の内容を厳密に選別したい場合に使う。
- Sentence formatでは、\{Sales\}のようなフィールド参照を含むテンプレート文を書いてデータ点の説明文を表示でき、Bold valuesで差し込まれた値を強調できる。Sentence format onlyをオンにすると、既存の項目一覧を消して文章だけを表示する構成にもできる。
- Sentence formatはフィールド パラメーターにも対応し、選択中のフィールド名と値の両方を文中で参照できる。階層のドリルアップ/ドリルダウン時は、in-scopeレベルを判定するmeasureをTooltipフィールドウェルに追加してテンプレートから参照すれば、階層ごとに自然な文面を出せる。
- Report page tooltipを使うと、ホバー カードを設計済みのレポートページに置き換えられ、選択したデータ点のフィルターも自動で引き継がれる。一方でレポートページ型ツールチップは対話不可で、スライサー操作やビジュアルのクリックはできないため、操作が必要な場合はdrillthroughページを使う。
- Chart-specific tooltipsはファネルチャートなどでグラフ種別に応じた補足情報を出す機能で、既定ではオンになっている。加えて、modern visual defaultsをプレビューで有効にすると、レポートページ型ツールチップ向けの小さめのキャンバスサイズを選べる。

<details><summary>English summary</summary>

Power BI visuals has generally made available the new Tooltip fields only and Sentence format only options, giving report authors precise control over which fields or sentence-based content appears on hover. Tooltip customization now ranges from adding fields to the default tooltip to curating fields, using sentence templates, or fully replacing the tooltip with a report page. A separate Help tooltip can also be used alongside data tooltips to explain the visual itself.

</details>

### VSCode Blog (1)

#### [How Prompt Tuning Improved GPT-5.5 in VS Code](https://code.visualstudio.com/blogs/2026/07/06/optimizing-vscode-coding-harness-model-providers)
- 公開日時: 2026-07-06T00:00:00.000Z
- 要約: VS CodeではGPT-5.5の既定システムプロンプトが、実験で勝ったTreatment B「LargePromptSections」に切り替わった。OpenAIと共同の2週間実験では、探索を抑えて編集後すぐ検証する構成を比較し、Treatment Bは遅延や上位尾部のトークン、ツール呼び出しで改善しつつ品質ガードレールはおおむね安定だった。
- なぜ重要か: 利用量課金でこのGPT-5.5エージェントを使う利用者に関係する。記事では、無駄な探索に使うトークンはそのまま待ち時間と支払いにつながり、根拠ある編集に早く到達できるエージェントは体験と請求額の両面で有利になると説明している。

**重要ポイント**
- 実験はVS Code上で2週間行われ、GPT-5.5エージェントのトラフィックをコントロール1群と処置2群に25/25/25で割り当て、残りは既定プロンプトのまま比較対象外で流した。
- Treatment Aは探索を減らすための単一で簡潔な注意喚起にとどめ、Treatment BはBefore\_the\_first\_editとAfter\_the\_first\_editの節を加え、局所仮説から最初の編集、直後の検証までの流れを明示した。
- 結果ではTreatment Bが最も強く、初回編集までの時間をp50で5.68%、p95で9.30%短縮し、p95総トークンを7.64%、平均ツール呼び出しを8.54%減らした。
- 品質面ではTreatment Bのcommit survival rateは+0.68%で有意差なしだった一方、10-minute survival rateは-0.44%で、統計的有意性は閾値をわずかに超えた程度だった。
- VS Code teamは総合評価でTreatment Bを採用し、LargePromptSectionsをGPT-5.5の既定システムプロンプトとして出荷した。

<details><summary>English summary</summary>

VS Code switched GPT-5.5's default system prompt to the winning Treatment B, LargePromptSections. In a two-week experiment with OpenAI, it compared a structure that limits exploration and validates immediately after edits, and Treatment B improved latency, upper-tail token use, and tool calls while keeping quality guardrails mostly stable.

</details>
