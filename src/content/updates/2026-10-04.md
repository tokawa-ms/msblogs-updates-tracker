#### [The Economics of Agent Optimization: How AI agent governance controls cost and proves ROI](https://azure.microsoft.com/en-us/blog/the-economics-of-agent-optimization-how-ai-agent-governance-controls-cost-and-proves-roi/)
- 公開日時: 2026-09-10T17:00:00.000Z
- 要約: Microsoft FoundryにおけるAIエージェントのガバナンスは、コストの可視化・制限・ROI検証を一体で進める運用として整理された。Foundryではプロジェクト別の推定コストやエージェント単位のコスト／トークン使用量を確認でき、AI Gateway経由でプロジェクト単位のトークン制限も実施できる。さらに、Azure OpenAIを含むAzure販売モデル向けのプロジェクト別コスト配賦はプレビュー、業務成果とコストを結び付けるROI for agentsはプライベートプレビューとして紹介されている。
- なぜ重要か: 企業内でAIエージェントを運用する開発者、プラットフォームチーム、IT、財務にとって重要なのは、請求後の予算アラートだけではなく、実行時に消費を止める制御と、成果に対する投資妥当性の両方が必要だと整理している点だ。記事は、Foundryが開発者向けのFinOpsと運用レバーを担い、Microsoft Agent 365がテナント全体の発見・保護・管理を担う役割分担も明確にしており、エージェント運用を個別実験から全社的な管理対象へ移す組織に影響する。

**重要ポイント**
- Foundryは、プロジェクト横断の推定コスト、個別エージェントのコストとトークン使用量、モデルコストを可視化する。ただし、これらは運用判断向けの推定値であり、財務精算の正式記録はMicrosoft Cost Managementと請求額だとされる。
- プロジェクト単位のコスト配賦に対応し、各Foundry projectの利用には自動でproject tagが付く。FinOpsチームはそのタグでCost Analysisを絞り込み、事業部門やチーム、ワークロード単位に配賦できるが、この機能はAzure OpenAIを含むAzure販売モデルで現在プレビューだ。
- AI Gatewayを構成すると、Foundry Control Planeでプロジェクト単位にtokens-per-minuteのレート制限と総トークンクォータを強制できる。上限超過時は429 Too Many Requests、クォータ枯渇時は403 Forbiddenを返し、クォータ期間は時間・日・週・月・年単位で設定できる。
- AI Gatewayのllm-token-limit policyは、サブスクリプション、アプリケーション、チーム、顧客、workload identityなどのキー単位で、レート制限や累積クォータ、またはその両方を適用できる。OpenAI互換API、Anthropic Messages API、MCP servers、agent-to-agent APIsに同じガバナンスモデルを適用できる一方、カウンターはゲートウェイごとに独立し、同時リクエストでは一時的な超過が起こり得る。
- ROI for agentsはFoundryのプライベートプレビュー機能で、成功した業務成果に紐づく価値と、そこに至るモデル／ツールコストを追跡し、Value generated、Total cost、Net value、ROIを計算する。ダッシュボードでは日次トレンド、モデルとツールのコスト分離、会話あたり平均価値、pass rate、improvement percentageによるバージョン比較が可能だ。

<details><summary>English summary</summary>

The article frames AI agent governance in Microsoft Foundry as an integrated practice of making costs visible, limiting spend, and proving ROI. Foundry can show estimated costs by project and cost/token usage by individual agents, and project-scoped token limits can be enforced through AI Gateway. It also notes that project-level cost attribution for Azure-sold models including Azure OpenAI is in preview, while ROI for agents that links business outcomes to costs is in private preview.

**Why it matters:** This matters to developers, platform teams, IT, and finance operating AI agents in enterprises because the article argues that budget alerts after billing are not enough; organizations also need runtime controls that can stop consumption and a way to judge whether the investment is justified by outcomes. It also clarifies the division of roles, with Foundry providing FinOps and operational levers for developers, while Microsoft Agent 365 handles discovery, protection, and management across the broader tenant estate, which affects organizations moving from isolated experiments to enterprise-wide agent governance.

**Key points**
- Foundry provides visibility into estimated costs across projects, cost and token usage for individual agents, and model costs. However, these are positioned as estimates for operational decisions, while Microsoft Cost Management and invoiced charges remain the system of record for financial reconciliation.
- It supports project-level cost attribution, and each Foundry project is automatically associated with a project tag on underlying usage. FinOps teams can filter Cost Analysis by that tag to allocate spending to business units, teams, or workloads, but this capability is currently in preview for Azure-sold models including Azure OpenAI.
- When AI Gateway is configured, Foundry Control Plane can enforce project-scoped tokens-per-minute rate limits and total token quotas. Requests over the rate limit return 429 Too Many Requests, exhausted quotas return 403 Forbidden, and quota periods can be hourly, daily, weekly, monthly, or yearly.
- The AI Gateway llm-token-limit policy can apply rate limits, cumulative quotas, or both per key such as a subscription, application, team, customer, or workload identity. The same governance model spans OpenAI-compatible APIs, the Anthropic Messages API, MCP servers, and agent-to-agent APIs, but counters are maintained per gateway and concurrent requests can cause small temporary overages.
- ROI for agents is a private preview feature in Foundry that tracks the value tied to successful business outcomes alongside the model and tool costs incurred to achieve them, then calculates Value generated, Total cost, Net value, and ROI. Its dashboard shows daily trends, separates model and tool costs, and supports version comparisons using average value per conversation, pass rate, and improvement percentage.

</details>

#### [The future of infrastructure resiliency starts with modernization](https://azure.microsoft.com/en-us/blog/the-future-of-infrastructure-resiliency-starts-with-modernization/)
- 公開日時: 2026-09-10T16:00:00.000Z
- 要約: Azure Infrastructure Resiliency Managerが新たに案内され、Azureはアプリケーション単位でレジリエンシー目標や重要度、ギャップを継続評価する運用を前面に出した。あわせてAzure Copilotのresiliency agentで推奨やテンプレート生成を支援し、Azure Managed Disks向けのper-disk resiliencyは一部リージョンでパブリックプレビューとなった。これにより、影響を受けたデータディスクだけを一時的に切り離し、VMや他ディスクの稼働継続を狙う。
- なぜ重要か: 分散アプリ、AIサービス、ハイブリッド/マルチクラウドを抱える組織ほど影響が大きい。記事は、停止や性能低下、データ損失が事業影響を持つ前提で、設計時の可用性対策だけでなく、変更に伴う継続評価と障害・サイバー攻撃を想定した復旧検証をAzure上で統合して進める必要性を示している。

**重要ポイント**
- Azure Infrastructure Resiliency Managerは、手動レビューや静的評価ではなく、アプリケーションレベルで目標設定、重要度把握、ギャップ特定、ポスチャ評価を継続実施する位置付け。
- 同マネージャーはAzure Copilotのresiliency agentを通じてAI支援を提供し、ワークロード記述、耐障害性のあるデプロイテンプレート生成、既存環境評価、目標に沿った推奨提示を行う。
- Azure Managed Disksのper-disk resiliencyは一部リージョンのパブリックプレビューで、長時間の接続断でも影響を受けたデータディスクだけをオフライン化し、復旧後に自動再接続する。
- 復旧面ではAzure Infrastructure Resiliency ManagerとAzure Chaos Studioで計画やフェイルオーバー手順を検証し、Azure Backupはimmutable vaultsやsoft delete、multi-user authorizationなどで信頼できる復旧ポイント維持を支援する。

<details><summary>English summary</summary>

Azure Infrastructure Resiliency Manager has been newly introduced, and Azure is emphasizing continuous application-level assessment of resiliency goals, workload criticality, and gaps. It also adds recommendations and template generation through the resiliency agent in Azure Copilot, while per-disk resiliency for Azure Managed Disks has entered public preview in selected regions. That approach aims to keep VMs and unaffected disks running by temporarily taking only the impacted data disk offline.

**Why it matters:** This matters most for organizations running distributed applications, AI services, and hybrid or multicloud environments. The article argues that because downtime, performance degradation, and data loss can have business consequences, Azure resiliency must cover not only design-time availability measures but also continuous reassessment as systems change and recovery validation for outages and cyberattacks.

**Key points**
- Azure Infrastructure Resiliency Manager is positioned to continuously handle application-level goal setting, workload criticality, gap identification, and posture assessment instead of relying on manual reviews and static assessments.
- The manager offers AI-assisted support through the Azure Copilot resiliency agent, including workload description, resilient deployment template generation, existing environment assessment, and recommendations aligned to resiliency goals.
- Per-disk resiliency for Azure Managed Disks is in public preview in selected regions; during extended connectivity loss, it can take only the affected data disk offline and automatically reattach it after connectivity is restored.
- For recovery, Azure Infrastructure Resiliency Manager and Azure Chaos Studio are used to validate plans and failover procedures, while Azure Backup supports trusted recovery points with features such as immutable vaults, soft delete, and multi-user authorization.

</details>

<details><summary>English summary</summary>

Microsoft has added three capabilities—Home, Code, and Autopilot—to the Copilot app, unifying chat, delegated work, app creation, and persistent agents in one experience. In Home, users can work with Word, Excel, and PowerPoint directly, while Code uses the same underlying technology as GitHub Copilot to build solutions from natural language. Home and Code are rolling out through the Frontier program, and Autopilot expands to private preview at the end of the month.

**Why it matters:** For Microsoft 365 knowledge workers, this makes it easier to move across document creation, delegated tasks, lightweight app building, and autonomous execution within Copilot, linking conversations more directly to real files and real work. Non-developers are especially affected because Code lowers the barrier to building small solutions, while IT teams get tenant-hosted execution, centralized plugin approval, and spending policy controls to support broader rollout with governance.

**Key points**
- Home brings Chat and Cowork together in one place, and Office in Copilot lets users create and update real Word, Excel, and PowerPoint files directly from Copilot.
- Code can generate apps, trackers, dashboards, and automations from natural language, runs in a sandboxed environment, and can be hosted securely within the tenant. It starts rolling out to Frontier at the end of the month, reaches broad availability in the following weeks, and is planned for preview later this year for Microsoft 365 Premium and Pro subscribers.
- Autopilot, formerly Scout, is a cloud-hosted personal agent that can continue recurring work and follow-ups without waiting for prompts. It has its own identity, memory, computer, and workspace inside the tenant, and its private preview expands at the end of the month.
- On pricing, Chat and apps like Word, Excel, and PowerPoint stay under the fixed-cost USL, while Cowork, Code, Autopilot, and frontier models use usage-based billing. FinOps for AI also expands spend management to cover Code and Copilot Managed Runtime.
