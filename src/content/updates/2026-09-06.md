#### [GPT-6 Astra: Frontier intelligence for work, now available in Microsoft Foundry](https://azure.microsoft.com/en-us/blog/gpt-6-astra-frontier-intelligence-for-work-now-available-in-microsoft-foundry/)
- 公開日時: 2026-09-03T18:15:00.000Z
- 要約: GPT-6 AstraがMicrosoft Foundryで全顧客向けに一般提供となり、複雑な業務判断から計画立案、成果物作成、アプリ横断の実行までを担うモデルとして位置づけられた。専用APIがない既存アプリを含むコンピュータ利用機能を備える一方、性能はタスクや設定で変動し、Foundry側でアクセス制御、承認、監視、人手チェックを組み合わせた運用が前提とされている。
- なぜ重要か: 複雑な業務をAIで実運用したい企業の開発者、アナリスト、事務・専門職部門、統制担当に影響する発表だ。記事では、ソフトウェア不具合の再現と原因調査、Power BIダッシュボード改善、文書や表計算・プレゼン作成、顧客記録更新など複数の業務シナリオが示されており、単なる対話支援ではなく部門横断の作業単位を担わせる方向性が強い。一方で、重要な操作には人手チェックを挟み、各組織が自らの規制要件に応じて制御を選定・設定する前提が明確にされている。

**重要ポイント**
- GPT-6 AstraはMicrosoft Foundryで全顧客向けにGAとなり、企業の複雑な業務判断と、業務アプリやシステムをまたぐ実行を支援する用途が明示された。
- コンピュータ利用機能は専用APIのないワークフローも含む既存アプリをまたいで使えるが、OpenAIの評価は一部ベンチマークでの結果であり、実際の性能はタスク、ツール、設定、安全策で変わる。
- FoundryはEntraによるID・アクセス管理、転送時/保存時暗号化、プライベートネットワーク、RBAC、コンテンツフィルタリング、監視、ガバナンスを組み合わせて提供する。なお、プロンプトと出力はモデル学習に使われないが、リスクをなくすものではなく、各組織に制御選定と設定の責任が残る。
- 提供形態はFoundry modelsのStandardとProvisioned Throughputで、提供地域はGlobalとUS Data Zone。Standardは従量課金、Provisioned Throughputは一貫したレイテンシと保証スループット向けの専有処理容量として説明されている。
- 標準課金の公表価格は100万トークン当たり、Globalの短コンテキストが入力10ドル・キャッシュ入力1ドル・キャッシュ書き込み12.5ドル・出力50ドル、長コンテキストが入力20ドル・出力75ドル。US Data Zoneは短コンテキストが11ドル/55ドル、長コンテキストが22ドル/82.5ドルで、Provisioned Throughputの米国Data ZoneはGlobal比10%増しとされた。

GPT-6 Astra is now generally available to all Microsoft Foundry customers and is positioned for complex enterprise work spanning decision support, planning, polished outputs, and action across applications. It can use computers across familiar apps, including workflows without dedicated APIs, but Microsoft says it should be deployed with access controls, approvals, monitoring, and human checkpoints because performance varies by task and configuration.

</details>

#### [How Microsoft’s Physical Security Engineering Team scaled hybrid operations with Azure Arc and Azure Virtual Desktop](https://azure.microsoft.com/en-us/blog/how-microsofts-physical-security-engineering-team-scaled-hybrid-operations-with-azure-arc-and-azure-virtual-desktop/)
- 公開日時: 2026-09-03T15:00:00.000Z
- 要約: Azure ArcとAzure Virtual Desktopの組み合わせにより、Microsoftの物理セキュリティ運用基盤は、世界中のデータセンターに分散したサーバーと運用アプリを共通モデルで管理できるようになった。ワークロードをAzureへ移さずに可視化、ガバナンス、自動化を集約し、パッチ適用や構成管理の負荷を下げた。さらにアプリ環境を対象インフラの近くへ移してAzure Virtual Desktop経由で提供し、アプリ起動時間は約12倍、リリースサイクルは約6倍改善した。
- なぜ重要か: この事例は、システムを現地に残したまま世界規模で統制したい運用チーム、特にデータセンターや物理セキュリティのようなハイブリッド環境の担当者に関係する。Azure Arcで分散サーバーの共通管理とガバナンスを行い、Azure Virtual Desktopで操作者向けの一貫した利用体験と詳細なセッション監視を得ることで、少人数でも拡大する運用基盤を支えやすくなることを示している。

**重要ポイント**
- Azure Arcは、現地近接性や自律運用を維持する必要がある物理セキュリティ向けワークロードをAzureへ移さず、Azureのコントロールプレーンから管理するために採用された。
- Azure Update Managerで分散環境のパッチ作業を集中管理し、チームによれば自動化で年間数千時間を削減した。あわせてAzure Policy、Guest Configuration、Azure Monitor、Log Analyticsで構成逸脱やシステム健全性を継続監視した。
- Azure Virtual Desktopではアプリ実行環境を対象インフラの近くへ移し、セッション経由で提供したことで、オペレーターが使う重要ツールの起動時間が約12倍改善した。
- 集中イメージ管理と自動ホスト刷新により、承認済みイメージからホストを再構築して一貫展開できるようになり、リリースサイクルは約6倍高速化した。以前は数週間から数か月かかった更新も数時間で完了できるようになった。

<details><summary>English summary</summary>

By combining Azure Arc and Azure Virtual Desktop, Microsoft’s physical security operations created a common model for managing servers and operational apps spread across its global datacenter footprint. Without moving workloads into Azure, the team centralized visibility, governance, and automation across hybrid infrastructure and reduced patching and configuration effort. Moving the app environment closer to the supporting infrastructure and delivering it through Azure Virtual Desktop improved app launch times by about 12x and release cycles by about 6x.

</details>
