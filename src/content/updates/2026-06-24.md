#### [I automated my job (and it made me a better leader)](https://github.blog/developer-skills/github/i-automated-my-job-and-it-made-me-a-better-leader/)
- 公開日時: 2026-06-23T16:00:00.000Z
- 要約: GitHub Copilot appの自動化機能を使い、筆者は会議準備や日次トリアージ、未対応タスク追跡など約40本の定期プロンプトを運用するようになった。自動化はカレンダー、メール、メッセージ、GitHubリポジトリの実作業コンテキストに接続して実行され、朝の準備や進捗把握の負担を減らした。筆者は特にAuDHDに伴う実行機能とワーキングメモリのばらつきを補うアクセシビリティ手段として位置付けている。
- なぜ重要か: この内容は、仕事の文脈が多方面に散らばりがちなリーダー層や、実行機能やワーキングメモリのばらつきがある神経多様性のある専門職にとって意味がある。筆者の説明では、自動化は人とのつながりを置き換えるのではなく、約束の追跡や準備の足場を担って注意の質を安定させ、対人対応により集中できるようにする。

**重要ポイント**
- GitHub Copilot appはmacOS、Windows、Linux向けの独立したデスクトップアプリで、リポジトリごとにブランチとworktreeを分けた並列セッションを走らせ、canvas上でエージェントの進捗をリアルタイムに見ながら操作できる。
- 朝の運用では、Meeting Prepが会議ごとの文脈を組み立て、Pre-Meeting Access Checkが招待に含まれる資料やリンクへのアクセス可否を確認し、Daily Triage DigestがGitHub、メール、メッセージから要対応事項を拾い上げる。
- 情報把握用の自動化として、Ship Decoderは過去24時間のGitHubの出荷内容を平易な言葉で整理し、Launch Radarは週次でチーム領域に関わる今後のローンチを抽出する。筆者はこの2本だけで、チャンネルを追って状況をつなぎ合わせる時間を毎日約1時間節約できると述べている。
- Stale Work Finderの例では、7日以上レビュー待ちの自分のPR、3日超の未レビュー割り当て、14日以上動きのない担当Issue、2週間超のDraft PRを検出し、停滞度別に並べて可視化する。

<details><summary>English summary</summary>

Using GitHub Copilot app automations, the author now runs about 40 scheduled prompts for meeting prep, daily triage, and stale-work tracking. These automations work across calendar, email, messages, and GitHub repositories to reduce the burden of preparation and context management. The author especially frames them as an accessibility aid for managing AuDHD-related inconsistency in executive function and working memory.

</details>

#### [GitHub joins coalition advocating for fixes to California AI Transparency Act to protect open source](https://github.blog/news-insights/policy-news-and-insights/github-joins-coalition-advocating-for-fixes-to-california-ai-transparency-act-to-protect-open-source/)
- 公開日時: 2026-06-23T15:48:00.000Z
- 要約: GitHubは、California’s AI Transparency Act（SB 942、SB 1000で修正提案）について、オープンソースを守るための限定的な修正を求める連合に参加した。現行草案のライセンス取消し条項は、恒久的かつ取消不能なオープンソースライセンスの実務と衝突し、特に共同開発型プロジェクトのサプライチェーンに不確実性を持ち込むと訴えている。連合は、法の透明性目標を保ちながら、EUのAI Act Transparency Code of Practiceに沿って、文書で下流利用者へベストプラクティスを通知する扱いへの整合を提案している。
- なぜ重要か: 影響を受けるのは、オープンソースのコードを使ってAIやソフトウェアを開発・再利用・共有する開発者や、共同体主導のプロジェクト、その周辺のソフトウェアサプライチェーンだ。GitHubは、修正によって透明性要件を保ちつつオープンソース開発との互換性を維持し、カリフォルニアでAIの説明責任と協調的なイノベーションの両立を図れると主張している。

**重要ポイント**
- GitHubはBlack Forest Labs、Hugging Face、Mozilla Corporationと連携し、California’s AI Transparency Actの修正を求める公開書簡に加わった。対象法案はSB 942で、SB 1000による修正案が前提になっている。
- 争点は、法案草案が下流利用者の義務違反時に開発者へライセンス取消しを求めている点で、オープンソースライセンスの恒久性・取消不能性と整合しないことだ。
- 連合は、この取消し要件がなくても法の目的は達成できるとし、AIシステムを改変・展開する開発者はすでに法律の直接適用対象で、執行手段も残ると説明している。
- 代替案として、EUのAI Act Transparency Code of Practiceに合わせ、オープンソースの特性を認めたうえで、文書内で下流利用者にベストプラクティスを通知するだけで十分だとしている。

<details><summary>English summary</summary>

GitHub joined a coalition seeking targeted amendments to California’s AI Transparency Act so its license-revocation provisions do not conflict with open source licensing. The group says the current draft could create uncertainty across collaborative software supply chains and proposes an EU-style approach that keeps the law’s transparency goals while relying on documentation-based downstream notices.

</details>

### Microsoft Fabric Blog (1)

#### [Microsoft Entra ID single sign-on for the Denodo connector in Power BI (Preview)](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Microsoft-Entra-ID-single-sign-on-for-the-Denodo-connector-in/ba-p/5193376)
- 公開日時: 2026-06-23T21:00:00.000Z
- 要約: Power BIのDenodoコネクタで、PreviewとしてMicrosoft Entra IDシングルサインオンがDirectQuery向けに利用できるようになった。これにより、セマンティックモデルを照会するユーザーは自身のEntra IDでDenodoに認証され、従来のKerberos Constrained Delegationや同期されたActive Directory前提を避けられる。オンプレミスのデータ ゲートウェイ経由でトークンをDenodoへそのまま渡し、Denodo側の行レベル・列レベルの認可を実ユーザーに対して適用できる。
- なぜ重要か: この変更は、Active Directoryを維持していないクラウドファースト企業や、複雑なハイブリッド構成を運用している組織に特に影響する。実ユーザーのIDをPower BIからDenodoまで一貫して渡せるため、Denodo側の行レベル・列レベルのアクセス制御や監査要件を、固定サービスアカウントではなく利用者本人に対して適用しやすくなる。

**重要ポイント**
- 対象はDirectQuery時のSSOで、ImportモードではユーザーIDはデータソースまで渡らない。Denodoコネクタ自体はImportとDirectQueryの両方をサポートするが、Entra ID SSOの効果はDirectQueryに限定される。
- 有効化にはPower BIテナント管理者がDenodo SSOとデータ ゲートウェイのEntra ID SSOを有効にし、Denodo接続設定で「Use SSO via Azure AD for DirectQueries queries」を選ぶ必要がある。
- 従来方式ではKCD設定、ゲートウェイのサービスアカウント設定、Active DirectoryとEntra IDの同期が必要だったが、新方式ではその複雑な委任チェーンを減らせる。
- Previewを試すには、DenodoサーバーがEntra IDトークン検証をサポートするバージョンであることと、オンプレミスのデータ ゲートウェイが最近のリリースであることを確認する必要がある。

<details><summary>English summary</summary>

The Denodo connector in Power BI now supports Microsoft Entra ID single sign-on for DirectQuery in preview. Users querying a semantic model can be authenticated to Denodo with their own Entra ID identity, avoiding the previous reliance on Kerberos constrained delegation and synchronized Active Directory environments. The gateway passes the user's token through to Denodo so Denodo can apply its own row-level and column-level authorization to the actual user.

</details>
