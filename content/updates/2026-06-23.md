### GitHub Blog (1)

#### [From pledge to practice: Building a more inclusive open source ecosystem](https://github.blog/open-source/from-pledge-to-practice-building-a-more-inclusive-open-source-ecosystem/)
- 公開日時: 2026-06-22T17:20:31.000Z
- 要約: GitHubは、オープンソースのアクセシビリティ向上に向けた自社の誓約を、この1年でハッカソン開催、サミット運営、文書整備、オープンツール提供へと具体化した。2026年5月には支援技術ハッカソンを開き、2025年10月には初のアクセシビリティサミットをAll Things Openと共催した。あわせて、支援技術利用者向けのGitHubアクセシビリティ文書や、GitHub ActionsとGitHub Copilotを使うAccessibility Scannerなど、日常開発に組み込みやすい実務リソースも拡充している。
- なぜ重要か: この取り組みは、障害のあるコントリビューター、メンテナー、教育者、アクセシビリティ実務者に直接関係する。記事によれば、実体験を持つ人々が文書作成やレビューに関わることで、GitHubやオープンソース参加の障壁を下げ、日々の開発フローにもアクセシビリティを組み込みやすくする。さらに2026年のイベントは、経験レベルを問わず実践的な貢献スキルを学ぶ場として位置付けられている。

**重要ポイント**
- 2026年5月、GitHub本社のサンフランシスコでOpen Source Assistive Technology Hackathonを2日間開催し、実際のアクセス障壁に取り組むオープンソース支援技術プロジェクトを共同開発した。参加支援として、NVDAスクリーンリーダーやキーボード操作に関するGitHub Learning Room、NV Accessのオフィスアワーも用意された。
- 支援対象のプロジェクト領域は、視覚障害者向けカメラ支援、PDFのアクセシブル形式変換、車いすソフト・ハードウェア、経路計画、スクリーンリーダーの発音改善、アクセシブルゲーム、点字ディスプレイ向け触覚体験など幅広い。
- 主流のオープンソース開発フロー改善では、2025年10月にノースカロライナ州ローリーで初回のOpen Source Accessibility SummitをAll Things Openと共催し、障害・アクセシビリティ・オープンソースの各コミュニティが、ソフトウェアのアクセシビリティ改善ロードマップを議論した。
- 実務向けリソースとして、ACCESSIBILITY.md作成やCI統合を含むベストプラクティス、GitHubアクセシビリティ文書、GitHub ActionsとGitHub Copilotを使うAccessibility Scanner、Figma向けAccessibility Annotation Toolkitを提供しており、課題起票や協業、開発工程への組み込みを支援する。
- 今後参加できる場として、2026年7月9日にバーチャル開催のOpen Source Accessibility Community Day、2026年10月19日にローリーでのOpen Source Accessibility Summitを案内している。前者ではハッカソン参加プロジェクトの成果や学び、今後必要な貢献先が共有される。

<details><summary>English summary</summary>

GitHub has turned its open source accessibility pledge into concrete work over the past year through hackathons, summits, documentation, and open tools. It held an assistive technology hackathon in May 2026 and the first accessibility summit in October 2025, while expanding practical resources such as accessibility documentation and the Accessibility Scanner built on GitHub Actions and GitHub Copilot.

</details>

### Microsoft Fabric Blog (1)

#### [Protect once, enforce everywhere: Protection policies for Power BI (Generally Available)](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Protect-once-enforce-everywhere-Protection-policies-for-Power-BI/ba-p/5223932)
- 公開日時: 2026-06-22T17:42:32.000Z
- 要約: Power BIでは、Microsoft Purviewのprotection policiesを使って、Fabricアイテムへのアクセスを感度ラベルに基づいて制御する考え方が示された。指定ラベルに保護ポリシーを関連付けると、許可されたユーザーやグループだけが実行時にアクセスを維持し、それ以外は自動的にブロックされる。現時点で直接の保護対象はPower BIのsemantic modelsで、そこを保護すると、そのモデルを参照する下流のレポートにも効果が及ぶ。
- なぜ重要か: 部門や外部関係者をまたいでPower BIのデータ活用を広げる組織や、ラベル設計を担うコンプライアンス担当に影響が大きい。記事では、1つのsemantic modelが多数のレポートに使われる前提で、分類に応じた制御をモデル層で一元適用し、下流継承によって分類の一貫性も保てる点が重要だと説明している。

**重要ポイント**
- 保護ポリシーは、ワークスペース権限ではなく感度ラベルを基準にアクセスを制御し、指定されたユーザーやグループ以外を実行時に自動遮断する。
- 現時点の対応対象はPower BIのsemantic modelsで、reportsやdashboardsを直接はサポートしない。ただしsemantic modelへのアクセスを止めると、接続先レポートはデータを返せず実質的に保護される。
- Power BIレポートを保護する実務上の要点は、保護ポリシー付きの感度ラベルをsemantic model、またはそれを支えるLakehouseやWarehouseなどのupstream Fabric itemsに適用することだ。
- ラベル付与は手動のほか、Default labels、Mandatory labeling、Downstream inheritanceで行え、semantic modelにラベルが付きポリシーが有効になると適用は自動化される。

<details><summary>English summary</summary>

Power BI can use Microsoft Purview protection policies to control access to Fabric items based on sensitivity labels. When a policy is tied to a label, only approved users or groups keep access at runtime and others are automatically blocked. In the current architecture, enforcement applies to semantic models rather than reports or dashboards directly, and protecting the model secures downstream reports as well.

</details>
