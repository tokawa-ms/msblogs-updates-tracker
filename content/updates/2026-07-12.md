#### [Built to bounce back: How Azure resiliency evolved](https://azure.microsoft.com/en-us/blog/built-to-bounce-back-how-azure-resiliency-evolved/)
- 公開日時: 2026-07-08T16:00:00.000Z
- 要約: Azure Infrastructure Resiliency ManagerがMicrosoft Build 2026で発表され、パブリックプレビューとして提供され、Resiliency in AzureやAzure Advisorなど分散していた耐障害性管理を単一の体験に統合した。Azureのレジリエンシー設計もリージョンペア固定から広がり、ゾーン優先や非ペアドリージョンを含むワークロード別の復旧設計を取れるようにしている。さらにResiliency Agentがリスクや設定不備の分析に加え、推奨変更のIaCテンプレート生成まで担う。
- なぜ重要か: 規制、主権、地政学的な制約を受ける組織や、Azure上で復旧設計を継続的に改善したい利用者にとって重要な内容だ。記事は、そうした環境では単なる可用性指標ではなく安全に復旧し続ける能力が重要だとしたうえで、従来ばらばらだった測定・改善手段を統合し、ゾーン耐性の確認や依存関係の発見を進めやすくする方向性を示している。

**重要ポイント**
- Azure Infrastructure Resiliency ManagerはBuild 2026で発表され、パブリックプレビューとして、Resiliency in Azure、Azure Advisor、Azure Chaos Studio、Azure Monitorを1つの体験に集約する。
- レジリエンシーの運用はStart resilient、Get resilient、Stay resilientというライフサイクルで整理され、まずゾーン耐障害性の姿勢を把握して隠れた依存関係や設計と実装のずれを見つけることを重視する。
- Resiliency Agentはワークロード全体を評価してリスクや設定不備、コスト・可用性・コンプライアンスのトレードオフを示し、推奨変更をIaCテンプレートとして生成できる。
- 復旧設計はリージョンペア前提に限定されず、主権・規制・地理条件に応じて非ペアドリージョンや非対称な復旧モデルを選ぶ想定が示されている。

<details><summary>English summary</summary>

Azure Infrastructure Resiliency Manager was introduced at Microsoft Build 2026 and is now in public preview, unifying previously separate Azure resiliency tools into a single experience. Azure’s resiliency model is also expanding beyond fixed region-pair assumptions toward zone-first, workload-specific recovery designs that can include non-paired regions. The Resiliency Agent adds risk analysis, misconfiguration detection, and IaC template generation for recommended changes.

</details>

#### [External key management for Azure Managed HSM is now in public preview](https://azure.microsoft.com/en-us/blog/external-key-management-for-azure-managed-hsm-is-now-in-public-preview/)
- 公開日時: 2026-07-07T16:00:00.000Z
- 要約: Azure Key Vault Managed HSM向けのExternal key managementがパブリックプレビューとなり、鍵素材をAzure外の自社運用HSMや信頼できる第三者のHSMに保持できるようになった。アプリケーションはManaged HSMとAzure Key Vault APIを従来どおり使いながら、必要な暗号処理だけを外部HSMに委譲できる。プレビュー開始時点では全Azureパブリックリージョンが対象だが、利用はゲート制でMicrosoftアカウントチームへの申請が必要だ。
- なぜ重要か: 政府、金融、重要インフラなど、規制や契約上の理由で暗号鍵をクラウド事業者環境の外に置かなければならない組織にとって、既存のManaged HSMとAzure Key Vault APIの使い方を大きく変えずに要件を満たす選択肢になる。一方で、外部HSMの可用性や運用は利用者側の責任になるため、広く一般向けの強化策というより、こうした厳格な主権・規制要件を持つ組織ほど影響が大きい。

**重要ポイント**
- 外部鍵はMicrosoftインフラ内に保存も通過もしない設計で、利用者が管理するハードウェア側だけで使われる。必要ならそのハードウェアを切り離して、関連する暗号処理を停止できる。
- 対象はManaged HSMを使ったカスタマー管理キー対応Azureサービスの保存データ保護で、Managed HSMの全ての鍵操作を外部化する機能ではない。制御を広げる代わりに、使える操作範囲は意図的に限定されている。
- 運用責任の一部は利用者側に移り、外部HSMプロキシやHSM自体の可用性、プロビジョニング、保護、拡張、監視、復旧を自社またはパートナーで担う必要がある。障害はManaged HSMのログに現れるが、切り分けと解決は利用者責任となる。
- プレビュー開始時の提供範囲は全Azureパブリックリージョンで、利用開始にはMicrosoftアカウントチームによる有効化が必要。料金はManaged HSMの標準価格のままでMicrosoftの追加課金はなく、ハードウェア費用やパートナーライセンス費用は利用者負担となる。

<details><summary>English summary</summary>

External key management for Azure Key Vault Managed HSM has entered public preview, allowing key material to stay on customer-owned or trusted third-party HSMs outside Azure. Applications can keep using Managed HSM and the Azure Key Vault API as before while delegating relevant cryptographic operations to the external HSM. At preview launch it is available in all Azure public regions, but access is gated and must be enabled through a Microsoft account team.

</details>
