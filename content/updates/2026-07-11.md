#### [Better tools made Copilot code review worse. Here’s how we actually improved it.](https://github.blog/ai-and-ml/github-copilot/better-tools-made-copilot-code-review-worse-heres-how-we-actually-improved-it/)
- 公開日時: 2026-07-10T15:57:47.000Z
- 要約: GitHub Copilot code reviewでは、独自のコード探索ツールをCopilot CLI由来のgrep、glob、viewへ移行した当初、レビューコストが上がり有用な指摘も減った。GitHubは原因をツール自体ではなく指示文にあると突き止め、PRのdiffから問いを立ててgrepとglobで絞り込み、必要な箇所だけviewで読むレビュー向けワークフローへ書き換えた。結果として本番では、レビュー品質を維持しながら平均レビューコストを約20%下げた。
- なぜ重要か: 影響を受けるのは、プルリクエストのレビューでCopilot code reviewを使う開発者と、共有ハーネスを使うCopilot製品を設計するGitHub側のチームだ。この記事は、共有ツールへの統合そのものではなく、diffに根ざした証拠収集に合わせて指示とベンチマークを調整したときに初めてコスト削減と品質維持が両立したこと、さらに同じ指示をCLIのような別用途へそのまま流用しても同じ成果にはならないことを示している。

**重要ポイント**
- Copilot code reviewは、従来のlist\_dir、search\_file/search\_dir、read\_codeを、CLIのglob、grep、viewに対応づけて置き換える移行を試みた。狙いは重複実装の削減と、複数のCopilot製品で共有できるコード探索基盤の整備だった。
- 最初のオフライン内部ベンチマークでは、エージェントがPRを調べる代わりにリポジトリ全体を閲覧するように振る舞い、広い検索と読み込みを繰り返してコンテキストを増やしていた。この挙動により、平均コストが上がり、有用なコメント数も減った。
- 見直した指示では、diffから具体的なレビュー質問を作り、パスが不明ならglob、候補ファイルやシンボルや呼び出し元の探索にはgrep、必要なファイルや行範囲が分かった時だけviewを使うよう定めた。さらに、安価な探索を先にまとめ、grep失敗時はより単純な検索へ、パス誤り時は推測読みではなくglobへ切り替えるよう誘導した。
- 本番では、調整後の挙動は対照群比で平均レビューコストを約20%下げ、品質面でも出荷を止めるシグナルは出なかった。一方で、同じような絞り込み指示をCopilot CLIへ適用しても同種の改善は得られず、同じツールでも製品ごとに仕事に合ったワークフローが必要だと示された。

<details><summary>English summary</summary>

GitHub Copilot code review initially became more expensive and caught fewer useful issues after moving from its own code exploration tools to the Copilot CLI’s grep, glob, and view tools. GitHub found the problem was the instructions, not the tools, and rewrote the workflow to start from the pull request diff, narrow with grep and glob, and read only exact evidence with view. In production, that change reduced average review cost by about 20% while maintaining review quality.

</details>
