### Azure Blog (1)

#### [GPT-6 Astra: Frontier intelligence for work, now generally available in Microsoft Foundry](https://azure.microsoft.com/en-us/blog/gpt-6-astra-frontier-intelligence-for-work-now-generally-available-in-microsoft-foundry/)
- 公開日時: 2026-09-03T18:15:00.000Z
- 要約: GPT-6 AstraがMicrosoft Foundryで全顧客向けに一般提供となり、複雑な業務の意思決定支援からアプリやシステムをまたぐ実行まで担うOpenAIの最新フロンティアモデルとして利用可能になった。FoundryではStandardとProvisioned Throughput、GlobalとUS Data Zoneの各構成で展開でき、EntraやRBAC、監視などの企業向け統制機能も組み合わせられる。料金はStandard Globalの短コンテキストで入力100万トークン当たり10ドル、出力50ドルなどが示されている。
- なぜ重要か: 複雑な業務をAIで本番運用したい企業の開発者、分析担当、業務部門にとって、APIがない既存アプリを含む横断実行と、認証・権限制御・監視を含む企業向け基盤を同じFoundryで使える点が重要だ。実験から本番への移行を進めやすくする一方、記事は性能や安全性が状況依存であり、各組織が自社のリスク要件に合わせて制御を構成する必要があることも強調している。

**重要ポイント**
- Astraは、曖昧で開放的な課題を複数段階で推論して計画化し、レビュー可能な成果物を作るだけでなく、ツール利用やcomputer useによってアプリ間を移動しながら多段の作業を進められるとされる。
- 対象業務として、複雑なバグ再現と修正案作成、Power BIでのダッシュボード改善、テンプレート準拠の文書・表計算・プレゼン作成、専用APIが限られる承認済み画面での記録更新やフォーム処理などが挙げられている。
- Foundry側の統制として、Microsoft EntraによるID・アクセス管理、保存時/転送時暗号化、プライベートネットワーク、ロールベースアクセス制御、コンテンツフィルタ、安全性評価、監視、ガバナンス機能が示されている。また、プロンプトと出力はモデル学習に使われない一方、リスクは残るため各組織が用途に応じて制御を選定・設定する責任がある。
- 提供形態はFoundry ModelsでのStandardとProvisioned Throughputで、地域はGlobalとUS Data Zone。価格はStandard Globalの短コンテキストで入力10ドル、キャッシュ済み入力1ドル、キャッシュ書き込み12.50ドル、出力50ドル、長コンテキストで入力20ドル・出力75ドル、Standard Data Zone (US) はそれぞれやや高い。Provisioned Throughputは配備形態で変動し、米国Data ZoneはGlobal比で10%上乗せとされる。
- computer useの性能については、OpenAIが一部評価で最先端水準だと報告しているが、実際の性能はタスク、ツール、設定、セーフガードで変わると明記されている。

<details><summary>English summary</summary>

GPT-6 Astra is now generally available to all customers in Microsoft Foundry, making OpenAI’s latest frontier model available for complex decision support and execution across applications and systems. In Foundry it can be deployed through Standard or Provisioned Throughput in Global and US Data Zone geographies, alongside enterprise controls such as Entra, RBAC, and monitoring. The article also lists pricing, including $10 per million input tokens and $50 per million output tokens for Standard Global short-context deployments.

</details>

### GitHub Blog (1)

#### [GitHub availability report: August 2026](https://github.blog/news-insights/company-news/github-availability-report-august-2026/)
- 公開日時: 2026-09-10T02:05:17.000Z
- 要約: GitHubは2026年8月に5件の障害でサービス全体の性能低下を受け、容量監視、リトライ方針、コアサービスのレジリエンス改善を進めた。8月11日には本番MySQLプライマリを初めてAzureで稼働させ、データベースとサービスのAzure移行を本番で前進させている。翌月も次のプライマリ移行、Azureへのトラフィック移行、容量管理とオートスケーリングの自動化を優先する方針だ。
- なぜ重要か: この報告は、GitHub Actions利用者、認証経由でissues、pull requests、API、Copilotを使う開発者、Copilot cloud agentを運用する組織、Kimi K3を設定した顧客に重要だ。8月の障害ではワークフローの開始・完了失敗、認証遅延、エージェント結果の遅延表示、特定モデルでの高い失敗率が起きており、どの利用形態が影響を受け、どこまで他モデルや時間経過で回避できたかを具体的に示している。

**重要ポイント**
- 8月11日に本番MySQLプライマリを初めてAzureで稼働させた。読み取りトラフィックも増え、移行済みサービスは60.4％、GitHubモノリスは64.3％、Git readsは54％までAzure側で到達した。
- authentication-coreの24テーブル群を最古の共有DB mysql1から移し、レプリカ負荷を毎秒約100万クエリ削減した。さらにクエリ衛生改善で毎秒12万クエリを減らし、1時間あたり約5万9000秒分の無駄なDB作業をなくした。
- GitHub Actionsではジョブルーティング変更でジョブの33％を制約のある本番クラスタから余力側へ移し、ピーク時のキャッシュCPU利用率を98％から80％へ下げた。GitHubはこれで推定3カ月分の余力を得たが、恒久対策ではなく当面の封じ込め策だと説明している。
- 8月20日のCopilot cloud agent障害では、少なくとも54組織でタスク状態と結果の反映遅延が平常を大きく超え、影響は測定対象のtask-status activityの37.5％でピークに達した。一方でタスク自体は完了しており、処理が追いつくと正しい状態と結果が表示された。

<details><summary>English summary</summary>

GitHub says five August 2026 incidents degraded performance across its services, prompting work on capacity monitoring, retry behavior, and core-service resiliency. It also ran a production MySQL primary from Azure for the first time on August 11 and plans to keep moving databases and service traffic to Azure while automating capacity management and autoscaling.

</details>
