#### [Decoding the new AI lingo: Loops, harnesses, squads, hill climbing… oh my!](https://github.blog/ai-and-ml/decoding-the-new-ai-lingo-loops-harnesses-squads-hill-climbing-oh-my/)
- 公開日時: 2026-09-02T21:00:00.000Z
- 要約: GitHub Podcastの最新エピソードでは、開発現場で増えているAI用語の意味と使い分けを整理し、loop engineeringやRalph loops、squads、harness engineering、hill climbing、モデルの公開形態の違いをまとめている。記事は、単発プロンプトから反復可能なエージェント運用へ進む考え方や、複数エージェントの分業、モデルを取り巻く仕組みや改善方法までを、開発ワークフローの観点で解説している。
- なぜ重要か: この内容は、AIを使った開発運用を理解したい開発者や、顧客環境への導入を支援する技術者に関係する。記事は用語の流行自体より、反復可能なワークフロー、検証方法、人の介在、モデルの信頼性や監査可能性をどう考えるかが重要だと示しており、複数エージェント運用やモデル選択を見極める助けになる。

**重要ポイント**
- Loop engineeringは、エージェントを単発で都度促すのではなく、定期実行や検証・エスカレーションを含む反復可能な仕組みとして設計する考え方だ。
- Ralph loopは詳細なタスクを与えて完了まで回し続けるループの実装例で、大きな仕事の分解には使える一方、反復のたびにトークンや計算資源を消費しやすい。
- Squadsは役割の異なる複数エージェントのチーム、fleetは同時並行で動くエージェント群を指し、要点は並列化と専門化にある。
- Harnessはモデルを実運用で役立てるための周辺システムで、ツールや権限、メモリ、文脈、オーケストレーションを含む。harness engineeringはその設計と改善を指す。
- Closed models、open weight models、open source modelsは公開範囲が異なり、open weightは重みを使えるが学習データや学習方法は必ずしも公開されず、open source modelsはモデル・コード・データ・学習プロセスまで検査や再利用、改変が可能だ。

The latest GitHub Podcast episode organizes the meaning and usage of AI terms increasingly heard in software development, covering loop engineering, Ralph loops, squads, harness engineering, hill climbing, and differences in model openness. It explains the shift from one-shot prompting to repeatable agent workflows, multi-agent specialization, the systems around models, and how those systems are improved in development practice.

</details>

#### [How we make AI coding more cost efficient without sacrificing task quality](https://github.blog/ai-and-ml/github-copilot/how-we-make-ai-coding-more-cost-efficient-without-sacrificing-task-quality/)
- 公開日時: 2026-09-02T18:00:00.000Z
- 要約: GitHub Copilotは、AIコーディングの効率化に向けて、役立つ文脈を残しながら反復的な出力を減らし、価値のない書式と冗長な指示を削り、完了したバックグラウンド作業を追加取得なしで渡す4つの改善を進めた。変更の焦点は、必要な情報は保ったまま、情報価値の低い出力や書式、結果取得のためだけの余計なやり取りを減らす点にある。
- なぜ重要か: 恩恵を受けるのはCopilot CLIだけでなく、同じハーネスを使うGitHub Copilot appやCopilot code reviewの利用者だ。不要な書式や取得専用ターンを減らすことで、開発者にとってはコンテキストウィンドウを実作業に回しやすくなり、記事でもこれらはモデルを賢くしたのではなく不要作業を除いた改善だと位置づけている。

**重要ポイント**
- 個々のツール出力を短くしても、欠落情報の回収でコマンド再実行や再読込が発生すると、タスク全体ではトークン消費と所要時間が増えることがある。効率は1回の応答ではなく、依頼から最終結果までの全体で評価すべきだ。
- 出力圧縮は保守的な方針に改められ、cat、git diff、git showなどのソース風や任意出力はそのまま返し、grep系の検索結果は内容を落とさず再構成し、install/build/test/progressの反復ノイズだけを十分な節約が見込める場合に選択的に圧縮する。
- viewツールでは、現在の編集フローで使われていない各行の行番号プレフィックスを削除した。これによりオフラインのエージェント型コーディングベンチマークで推論コストが約5%下がり、Copilot CLIのオンライン実験でもユーザー1人あたりの平均日次推論コストが約3%低下した。
- task toolのプロンプトはメタプロンプティングでおよそ半分まで短縮されたが、最初のオンライン実験では独立エージェントを直列化する退行が見つかった。修正後の出荷版では1ターンあたり約1,300トークンを削減し、セッション全体のプロンプトトークンを約1.8%、アクティブ時間当たりの正規化コストを2.9%下げた。
- バックグラウンドで終わったシェル実行やサブエージェントの結果は、対象となる完了通知をまとめて既存のtool-result形式で直接渡すようになり、完了後の取得専用ターンを減らした。まだ実行中の作業に対する明示的な読み出し動作は従来どおりで、AI Credits基準の平均トークン関連使用量は約2.3%下がった。

<details><summary>English summary</summary>

GitHub Copilot is rolling out four AI-coding efficiency improvements: reduce repetitive output while preserving useful context, remove valueless formatting and bloated instructions, and deliver completed background work without an extra retrieval step. The aim is to cut low-value output, formatting, and retrieval-only interactions without dropping the information the agent needs.

</details>
