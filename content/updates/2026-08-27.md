### GitHub Blog (1)

#### [GitHub Copilot app for Beginners: Automate Dependabot pull request triage](https://github.blog/ai-and-ml/github-copilot/github-copilot-app-for-beginners-automate-dependabot-pull-request-triage/)
- 公開日時: 2026-08-26T20:12:53.000Z
- 要約: GitHub Copilot appでは、Dependabotのオープンなプルリクエストを毎日自動でレビューし、リスク別の整理、CI通過確認、次の対応の要約まで行う自動化を設定できる。対象リポジトリを選び、自然言語で依頼内容を記述すると、個別PRの一覧ではなく安全なパッチ更新、minor/majorの分類、追加調査が必要な依存関係をまとめた結果を返し、必要ならその文脈のままCopilotセッションに引き継げる。
- なぜ重要か: DependabotのPRが頻繁に発生し、破壊的変更に当たる可能性もあるプロジェクトの保守担当者にとって、反復的な一次切り分けをCopilotに任せ、朝の時点でどの更新がマージ可能でどれが精査対象かを把握しやすくする点が重要だ。記事では、日常的なルーチン作業を自動化し、人が専門的な判断が必要な作業に時間を使えるようにする用途として位置付けている。

**重要ポイント**
- 自動化のトリガーはManual、Hourly、Daily、Weekly、issue作成時から選べ、Dependabotレビューのような定期保守にはdaily scheduleが向く例として示されている。実行場所はcloudかlocal machineを選択できる。
- タスク内容は自然言語で指定し、例ではオープンなDependabot PRのリスク分類、安全なpatch/minor更新の識別、各PRのCI確認、推奨される次の対応の要約まで依頼している。対象のrepository選択後は、scheduled runを待たずにCreate and Runで即時実行もできる。
- 完了後の出力は個別PRの羅列ではなく要約で、安全なpatch updateの一括化、minorとmajor version upgradeの分離、passing CIの識別、追加調査が必要な依存関係の強調が行われる。
- 追加対応が必要な更新はautomation resultsから新しいCopilot sessionに直接進められ、その文脈を引き継げる。さらに各automation runは保存され、実行時刻、実施したactions、生成したresultsを後から確認できる。

<details><summary>English summary</summary>

GitHub Copilot app can be set up to automatically triage open Dependabot pull requests on a daily schedule, grouping updates by risk, checking CI status, and returning a concise action summary. After selecting a repository and describing the task in natural language, it summarizes safe patch updates, separates minor and major upgrades, flags dependencies needing deeper investigation, and can carry that context into a follow-up Copilot session.

</details>

### VSCode Blog (1)

#### [Introducing the Agent Host for persistent, portable agent sessions](https://code.visualstudio.com/blogs/2026/08/26/agent-host-architecture)
- 公開日時: 2026-08-26T00:00:00.000Z
- 要約: VS CodeのAgent Hostは、エージェントセッションを専用プロセスで保持する方式に変わり、開始したフォルダーやエディターウィンドウを閉じても処理を継続できるようになった。あわせてopenなAHPが導入され、エディター、Agents window、別マシン、ブラウザー間で同じライブセッションを同期して扱える。最新版のVS Code StableとInsidersで有効化されており、CopilotやClaudeなど異なるハーネスでも共通のセッション体験を提供する。
- なぜ重要か: 長時間動くエージェント作業をVS Codeで使う開発者は、セッションが特定のフォルダーやウィンドウに依存しなくなることで、画面や接続先を切り替えても同じ作業を追跡・操作しやすくなる。また、AHPが公開されたことで、独自クライアントやツールを実装する開発者も同じセッション状態に接続し、承認やツール提供を組み込める。

**重要ポイント**
- 最新版のVS Code StableとInsidersでAgent Hostが有効化され、エディターウィンドウで始めたセッションをAgents windowでも同じライブセッションとしてそのまま扱える。
- ローカルでは、作業中にフォルダーを閉じてもアクティブなターンは継続するが、ローカルセッションを維持するにはVS Code自体は起動したままである必要がある。
- リモートセッションにも対応し、別マシン上のワークスペースでAgent Hostを動かしたまま、デスクトップ版やWebから進捗確認、変更レビュー、セッション管理を行える。SSH、dev tunnels、Web向けのセットアップ案内もある。
- AHPは公開プロトコルで、standaloneのAgent Hostをcode agent hostまたはcode-insiders agent hostで起動できる。接続用クライアントライブラリはRust、TypeScript、Kotlin、Go、Swift向けが案内されている。

<details><summary>English summary</summary>

VS Code's Agent Host moves agent sessions into a dedicated process so work can continue even after the original folder or editor window is closed. With the open AHP protocol, the same live session can stay synchronized across the editor, the Agents window, other machines, and the browser. It is enabled in the latest VS Code Stable and Insiders and provides a common session experience across different harnesses such as Copilot and Claude.

</details>
