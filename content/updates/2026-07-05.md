#### [Proving application resilience on Azure with Chaos Studio](https://azure.microsoft.com/en-us/blog/proving-application-resilience-on-azure-with-chaos-studio/)
- 公開日時: 2026-07-01T16:00:00.000Z
- 要約: Azure Chaos Studio Workspacesは、Azureで実際に起きる障害パターンに沿って回復性を検証できる新しいワークスペース機能として、現在パブリックプレビューで提供された。サブスクリプションやリソースグループを対象に、管理IDが適用可能なシナリオを自動推奨し、Zone DownやDNS Outage、データベースフェイルオーバーなどの訓練を実行できる。GAは変更の可能性付きで2026年後半を予定している。
- なぜ重要か: Azure上で障害時の挙動を本番前に確かめたい開発・運用チーム、特にAIアプリケーションを本番投入するチームに関係する内容だ。記事は、設計上の冗長化だけでは不十分で、構成やアプリケーションロジックが障害下で持ちこたえるかを実証する必要があると位置付ける。実行後のレポートは変更管理や監査証跡にも使えるため、現場チームだけでなくレビューする管理側にも影響する。

**重要ポイント**
- Workspacesは新しい最上位リソースとして導入され、対象のサブスクリプションまたはリソースグループを指定すると、管理IDが範囲内のリソースを検出し、該当シナリオを推奨する。現時点ではパブリックプレビューで、GAは2026年後半予定だが変更の可能性がある。
- 提供開始時点で、Availability Zone Down、DNS Outage、Microsoft Entra ID Outage、Event-Driven Messaging Disruptionなどのキュレーション済みシナリオが利用できる。Cache StampedeのApp Service process-crash版は現時点でWindows App Service plansのみ対応する。
- キュレーション済みシナリオに合わない場合は、Azure portalのScenario Designerでドラッグアンドドロップにより独自シナリオを作成できる。さらに、CPUやメモリ圧迫といったVM agent faultsもWorkspaces内で実行可能だ。
- 運用連携として、GitHub Copilot向けChaos Studio Skillと、同じ操作を型付きツールとして公開するMCP serverが同時に提供される。どちらも同じChaos Studio APIと利用者自身のAzureサインインで動作し、すぐ試せる。

<details><summary>English summary</summary>

Azure Chaos Studio Workspaces is now in public preview as a scenario-based way to test real Azure outage patterns for application resilience. A Workspace can target a subscription or resource group, use managed identity to recommend applicable scenarios, and run drills such as Zone Down, DNS Outage, and database failover. GA is targeted for late 2026, subject to change.

</details>

#### [Azure IaaS: How to design, build, and optimize cloud infrastructure for long-term cost efficiency](https://azure.microsoft.com/en-us/blog/azure-iaas-how-to-design-build-and-optimize-cloud-infrastructure-for-long-term-cost-optimization-efficiency/)
- 公開日時: 2026-06-30T16:00:00.000Z
- 要約: Azure IaaSの長期的なコスト最適化に向けて、コンピュート、ストレージ、ネットワークの各層で設計・運用時に見直すべき効率化策が整理された。具体的には、VMの適正サイズ選定と料金オプションの組み合わせ、ストレージの階層化とライフサイクル管理、ネットワークの冗長化とログ収集の最適化を継続的に行う考え方を示している。あわせて、Azure IaaS Resource Centerで関連ガイダンスや技術資料を参照できるとしている。
- なぜ重要か: AI対応、既存アプリのモダナイズ、移行、将来の拡張を進めるAzure利用組織にとって、コスト増の原因を個別製品ではなくインフラ全体の設計判断として見直せる点が重要だ。特に、運用開始前から本番後まで継続的に最適化する前提を明示しており、性能や可用性を維持しながら無駄な容量、過剰な保存、不要なログ保持を減らしたいチームに直接関係する。

**重要ポイント**
- コンピュートでは、最安値を選ぶのではなく、ワークロード要件に合わせてVMのアーキテクチャや性能を選び、Pay-As-You-Go、Azure savings plans、Azure Reservations、Azure Spot Virtual Machinesを組み合わせて実使用に沿ったコスト配分を行うべきだとしている。
- 大規模なコンピュート環境では、Azure Virtual Machine Scale Setsによる自動スケールやAzure Compute Fleetによる容量・可用性・価格性能のバランス調整を使い、過剰配置を避けながら運用負荷も下げる方針を示している。
- ストレージでは、Premium SSD v2、Ultra Disk、Azure Elastic Storage Area Network (SAN)、Azure Files、Azure NetApp Files、Azure Blob Storage tiersなどを用途別に選び、アクセス頻度に応じた自動階層化とライフサイクルポリシーで長期コストを抑えるとしている。
- ネットワークでは、ExpressRoute MetroやZone Redundant NAT Gatewayなどでレジリエンシーとスケーラビリティを高めつつ、ログは必要なデータに絞るフィルタリングや分析で保存量と調査負荷を減らす考え方を示している。
- 最適化は単発の移行や価格判断では終わらず、利用状況や新機能に合わせて継続的に見直す運用規律だと位置づけており、Azure Copilotによるリアルタイム洞察、AIベースの推奨、自動最適化にも触れている。

<details><summary>English summary</summary>

Azure IaaS outlined long-term cost optimization practices across compute, storage, and networking. It emphasizes right-sizing VMs and pricing models, automating storage tiering and lifecycle policies, and improving network resiliency and logging efficiency as an ongoing operational discipline, with additional guidance available through the Azure IaaS Resource Center.

</details>
