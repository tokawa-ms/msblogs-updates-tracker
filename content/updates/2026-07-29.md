#### [Frontier models and production agents: Advancing Microsoft Foundry for the agentic era](https://azure.microsoft.com/en-us/blog/frontier-models-and-production-agents-advancing-microsoft-foundry-for-the-agentic-era/)
- 公開日時: 2026-07-09T17:00:00.000Z
- 要約: Microsoft Foundryは、GPT-5.6シリーズ、APAC向けのAsia-Pacific Data Zone、Foundry Agent Serviceの本番向け機能を一般提供し、AIエージェントを単一基盤で構築・運用・配布できるようにした。Foundry Agent Serviceではhosted agentsやToolboxesなどの本番機能がGAとなり、Microsoft 365向けの配布経路も用意される。これにより企業は、モデル選択から実行基盤、統制、配布までを分断された複数製品にまたがらず扱える。
- なぜ重要か: 恩恵を受けるのは、既存の開発環境からそのまま本番エージェントを展開したい企業開発チームと、APACで地域内処理や統制を重視する組織だ。Foundryがモデル、実行基盤、観測・評価、Microsoft 365への配布までをまとめることで、分断されたツールを個別に組み合わせずに、実験段階から大規模運用へ移しやすくなる。

**重要ポイント**
- Microsoft Foundry ModelsとFoundry Agent ServiceでGPT-5.6シリーズをGA。Solは高度な推論やコード重視シナリオ向け、TerraはGPT-5.5並みの性能をより低コストで狙う日常用途向け、Lunaは高速・低価格で高ボリュームかつ低遅延の用途向けに位置付けられている。
- 最新GPT-5.6は既存28のグローバルリージョン向けに、Global Standard、Global Priority Processing、Data Zones Standard、Global Provisionedで初日から提供される。Standard Globalの価格は100万トークン当たり、Solが入力5.00ドル・出力30.00ドル、Terraが入力2.00ドル・出力12.00ドル、Lunaが入力0.20ドル・出力1.20ドルで、SolのAzure OpenAIメータードAPIは2026年9月1日から少なくとも11月30日まで入力4.00ドル・出力20.00ドルの販促価格になる。
- Asia-Pacific Data ZoneがGAとなり、APACの顧客はデータ処理をアジア太平洋域内に維持したままfrontier OpenAI modelsを実行できる。FoundryはGlobal、Data Zone、Regionalの展開オプションをそろえ、主権・コンプライアンス・性能要件に合わせた配置を選べる。
- Foundry Agent Serviceではhosted agents、Voice Live対応のhosted agents、ToolboxesがGA。さらにMicrosoft TeamsとMicrosoft 365 Copilotへの公開は翌週からGAとなり、構築したエージェントを業務アプリに届けやすくする。
- 運用面では、Memory and routinesはpublic preview、hosted agents向けtracing and evaluationはGA、agent optimizerはpublic preview、ROI for agentsはprivate previewとして提供される。エージェントの状態保持、挙動の可視化、構成最適化、価値とコストの把握を段階的に追加している。

Microsoft Foundry has generally released the GPT-5.6 series, the APAC Asia-Pacific Data Zone, and production capabilities in Foundry Agent Service, making it a single platform for building, running, governing, and distributing AI agents. Hosted agents and toolboxes are now GA, and the platform is positioned to cover model choice, runtime, controls, and distribution without requiring separate disconnected services.

#### [Accelerate modern Linux workloads with Azure Files](https://azure.microsoft.com/en-us/blog/accelerate-modern-linux-workloads-with-azure-files/)
- 公開日時: 2026-06-29T15:00:00.000Z
- 要約: Azure Filesは、Linux向けのフルマネージドファイルストレージとして、NFSベースのモダンLinuxワークロード向け機能を拡充した。AI推論では新しいZonal placementとprovisioned v2 billing modelにより、GPU VMと同一ゾーン配置やIOPS・スループットの個別調整を可能にする。AKS向けにはCSI driver連携に加え、新しいfile share experienceで1サブスクリプション・1リージョン当たり最大10,000共有と約2.5倍高速なプロビジョニングをうたい、既存NFSアプリ向けにAzure Storage MoverとAzure Migrate support for NFSも打ち出した。
- なぜ重要か: 恩恵を受けるのは、GPUを使うAI推論基盤、AKSでRWX共有ストレージを必要とするクラウドネイティブ運用、既存のLinux/NFS業務アプリをAzureへ移す企業、そしてSMB 3.xやNFS 4.1前提で統合するISVやパートナーだ。Azure Filesが標準プロトコルと移行・保護機能をまとめて提供することで、既存アプリを大きく変えずに共有ストレージをAzureへ集約しやすくなる。

**重要ポイント**
- AI推論では、モデル重みを各レプリカが個別に持つのではなく共有ファイル共有から同時に読み込めるため、コンテナイメージの肥大化や重複コピーを避けつつ、小規模から中規模モデルでは新規レプリカを数秒で立ち上げられるとしている。Linux NFSのnconnectマウントオプションにも対応する。
- AIやデータ集約型ワークロード向けには、新しいZonal placementでGPU仮想マシンと同じ可用性ゾーンにファイル共有を配置でき、provisioned v2 billing modelでIOPSとスループットを独立して設定できる。
- クラウドネイティブ領域では、Azure Files CSI driverを通じてAKSと統合し、StorageClassesによる動的プロビジョニング、拡張可能な永続ボリューム、ReadWriteManyの共有アクセスを提供する。さらに新しいfile share experienceは、1サブスクリプション・1リージョン当たり最大10,000共有と約2.5倍高速なプロビジョニングをうたう。
- 既存のLinux/NFS業務アプリ移行向けには、Azure Storage MoverとAzure Migrate support for NFSで評価・計画・移行を支援し、運用開始後はsnapshots、soft delete、NFSのencryption in transitで復旧性と保護を強化できるとしている。
- パートナーやISV向けには、独自APIではなくSMB 3.xとNFS 4.1の標準プロトコルを前面に出し、NFS Snapshot、Soft Delete、NFS shares向けREST APIを通じてBCDR、データ移動、管理、アプリ連携を組み込みやすくした。

<details><summary>English summary</summary>

Azure Files expanded its support for modern Linux workloads with new NFS-focused capabilities. For AI inference, new zonal placement and the provisioned v2 billing model enable same-zone placement with GPU VMs and independent tuning of IOPS and throughput. For AKS and migrations, Microsoft also highlights CSI integration, a new file share experience with up to 10,000 shares per subscription per region and about 2.5x faster provisioning, plus Azure Storage Mover and Azure Migrate support for NFS.

</details>

#### [Disrupting supply chain attacks on npm and GitHub Actions](https://github.blog/security/supply-chain-security/disrupting-supply-chain-attacks-on-npm-and-github-actions/)
- 公開日時: 2026-07-28T16:00:00.000Z
- 要約: npmとGitHub Actionsでは、サプライチェーン攻撃を断つための保護策が2026年にかけて拡充された。npmでは高影響アカウントのメール変更や2FA復旧コード使用後に72時間の読み取り専用化を導入し、trusted publishingのCircleCI対応で長期資格情報の削減を後押しする。GitHub Actionsではactions/checkoutの既定動作を見直してフォーク由来の未信頼コード取得を抑え、未信頼ワークフローから共有キャッシュを書き換えられないようにした。
- なぜ重要か: 影響を受けるのは、npmメンテナー、GitHub Actionsを運用するチーム、そしてエンタープライズ管理者やその利用者だ。記事の施策は、未信頼コードの実行、資格情報の流出、漏えい後の悪用、悪性リリースの取り込みまで攻撃の各段階を分断するよう設計されており、侵害時にも自己サービスで資格情報を即時失効でき、Dependabotの既定3日クールダウンで通常更新の取り込み猶予も得られる。

**重要ポイント**
- 2026年6月、npmは高影響アカウント向けに、メール変更または2FA復旧コード使用後の72時間読み取り専用化を導入した。フィッシング後にアカウントがすぐ攻撃に使われるのを遅らせる狙いがある。
- 2026年6月、GitHub Actionsのactions/checkoutは、よく悪用されるトリガーでフォークからの未信頼コードを既定でチェックアウトしないよう変更され、明示的なオプトアウト時のみ従来動作を選べる。旧版へのバックポートも行われた。
- 2026年4月にnpm trusted publishingがCircleCIをサポートし、2026年5月にはstaged publishingが追加された。後者はnpm CLIまたはnpmjs.comでの追加承認と2FA認証がないと公開を完了できないオプトイン制御だ。
- Actions network firewallは現時点でtechnical previewで、ワークフロー実行時の全ての外向き通信を記録する。将来は通信遮断やポリシー適用も予定されているが、記事時点では主機能はログ取得だ。
- npm v12ではinstall-time scriptsが既定で無効化され、gitまたはリモートURL経由の依存関係も既定で無効化される予定だ。さらに2026年7月からDependabotの通常のバージョン更新PRはリリース公開後少なくとも3日待機し、セキュリティ更新は即時に作成される。

<details><summary>English summary</summary>

npm and GitHub Actions expanded supply-chain defenses in 2026. npm added a 72-hour read-only lock for high-impact accounts after email changes or 2FA recovery use and extended trusted publishing to CircleCI to reduce long-lived credentials. GitHub Actions changed checkout defaults to avoid pulling untrusted fork code and made shared caches read-only for less trusted workflows.

</details>
