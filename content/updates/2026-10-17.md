#### [Microsoft named a Leader in the 2026 Gartner® Magic Quadrant™ for Server Virtualization Platforms](https://azure.microsoft.com/en-us/blog/microsoft-named-a-leader-in-the-2026-gartner-magic-quadrant-for-server-virtualization-platforms/)
- 公開日時: 2026-10-14T19:00:00.000Z
- 要約: Microsoftのサーバー仮想化関連技術は、2026年のGartner Magic Quadrant for Server Virtualization PlatformsでLeaderに位置付けられた。記事では、単なるハイパーバイザー選定ではなく、AzureとAzure Arcでクラウド、データセンター、エッジをまたぐ運用の一貫性を確保し、Hyper-VでAzure、Azure Local、Windows Serverに共通の仮想化基盤を提供する構成として、その価値を説明している。
- なぜ重要か: この内容は、クラウド、データセンター、エッジ、主権環境をまたいでインフラを運用する企業のIT部門に関係する。記事は、別々の運用モデルを増やさずに共通の管理・ガバナンス・セキュリティと仮想化基盤を維持できるというMicrosoftの方向性を示しており、AIで分散環境が広がるほどこの論点の重要性が増すと説明している。ただし本文でも、Gartnerの評価は事実の断定ではなく同社調査部門の意見だと明記している。

**重要ポイント**
- Microsoftは2026年版のGartner Magic Quadrant for Server Virtualization PlatformsでLeaderとされた。記事が引用するGartnerレポートの日付は2026年9月14日。
- Azureはクラウド、データセンター、エッジで共通の管理・ガバナンス・セキュリティを提供し、Azure Arcはその機能を分散インフラへ拡張すると説明されている。
- Hyper-VはAzure、Azure Local、Windows Serverをまたぐ共通の仮想化基盤として位置付けられ、ワークロードの実行場所が変わっても一貫したインフラ層を維持する考え方が示されている。
- Microsoftは、AIの普及でモデル、エージェント、アプリケーション、データが複数環境にまたがるため、共通の管理、ガバナンス、セキュリティ、基盤の必要性がさらに高まると主張している。

<details><summary>English summary</summary>

Microsoft's server virtualization-related technologies were positioned as a Leader in the 2026 Gartner Magic Quadrant for Server Virtualization Platforms. The article explains their value not as a simple hypervisor choice, but as a model that combines operational consistency across cloud, datacenter, and edge through Azure and Azure Arc with a common virtualization foundation across Azure, Azure Local, and Windows Server through Hyper-V.

**Why it matters:** This matters to enterprise IT teams operating infrastructure across cloud, datacenter, edge, and sovereign environments. The article presents Microsoft's direction as maintaining common management, governance, security, and a virtualization foundation without multiplying operating models, and says this becomes more important as AI expands distributed environments. It also explicitly notes that Gartner's evaluation reflects the opinions of its research organization and should not be treated as statements of fact.

**Key points**
- Microsoft was named a Leader in the 2026 edition of the Gartner Magic Quadrant for Server Virtualization Platforms. The Gartner report cited in the article is dated September 14, 2026.
- Azure is described as providing common management, governance, and security across cloud, datacenter, and edge, while Azure Arc extends those capabilities to distributed infrastructure.
- Hyper-V is positioned as a common virtualization foundation across Azure, Azure Local, and Windows Server, with the idea of maintaining a consistent infrastructure layer even as workload locations change.
- Microsoft argues that as AI spreads models, agents, applications, and data across multiple environments, the need for common management, governance, security, and infrastructure becomes even more important.

</details>

### Microsoft 365 Blog (1)

#### [Introducing the new Copilot with Home, Code and Autopilot](https://blogs.microsoft.com/blog/2026/09/25/introducing-the-new-copilot-with-home-code-and-autopilot/)
- 公開日時: 2026-09-25T12:07:25.000Z
- 要約: Microsoft Copilotアプリは、開始地点となるHome、自然言語で社内向けソリューションを作れるCode、継続稼働する個人向けエージェントAutopilotを追加し、Word・Excel・PowerPointの機能も体験内に統合した。HomeとCodeはFrontier programで今後数週間かけて展開され、Autopilotは月末にプライベートプレビューを拡大する。あわせて、Copilotやエージェントの支出管理を支援するFinOps for AI機能も発表した。
- なぜ重要か: Copilotを日常業務で使う従業員、社内向けツールを作る部門ユーザー、権限やコストを管理するIT・管理者に影響する。1つのCopilotで質問、委任、構築、自動化まで扱えるようになり、非開発者にも作成範囲が広がる一方で、プラグイン承認や支出ポリシー管理も集中して行えるため、組織内での利用拡大と運用統制を同時に進めやすくなる。

**重要ポイント**
- HomeはChatとCoworkを1か所にまとめ、Copilot内からWord、Excel、PowerPointの実ファイルを作成・更新できる。
- CodeはGitHub Copilotと同じ基盤技術を使い、サンドボックス環境とテナント内ホスティングに対応する。Frontierには月末から展開され、数週間後に広く利用可能になり、Microsoft 365 PremiumとProの購読者向けプレビューは年内予定。
- Copilot Managed Runtimeは、企業のMicrosoft 365環境内でコードを安全に動かすホスティング基盤としてプレビュー提供され、Code内からも利用できる。
- 業務コンテキスト拡張では、Fabric IQがChatとCoworkで本日から一般提供され、Dynamics 365とPower Platformのデータやワークフロー連携は今後1か月でパブリックプレビュー展開される。新しいプラグインレジストリも展開中で、数週間以内に各画面で一般提供される。
- 料金と運用管理では、ChatやWord、Excelなどは固定費のUSL、Cowork・Code・Autopilotや先端モデルは従量課金のUBBを使い分ける。Agent 365のコスト管理はCodeとCopilot Managed Runtimeまで拡張され、Copilot Studio製エージェント対応は10月予定だ。

<details><summary>English summary</summary>

The Microsoft Copilot app adds Home as a starting point, Code for building internal solutions in natural language, and Autopilot as a persistent personal agent, while also bringing Word, Excel, and PowerPoint directly into the experience. Home and Code will roll out through the Frontier program in the coming weeks, and Autopilot expands to private preview at the end of the month. Microsoft also announced new FinOps for AI capabilities to help manage spending on Copilot and agents.

**Why it matters:** This affects employees who use Copilot for daily work, business users who build internal tools, and IT and administrators who manage permissions and costs. A single Copilot can now handle asking, delegating, building, and automating, while extending creation to non-developers. At the same time, centralized plugin approval and spending policy controls make it easier for organizations to expand usage while maintaining operational governance.

**Key points**
- Home combines Chat and Cowork in one place and can create or update real Word, Excel, and PowerPoint files directly from Copilot.
- Code uses the same underlying technology as GitHub Copilot and supports a sandboxed environment and secure tenant hosting. It starts rolling out to Frontier at the end of the month, reaches broad availability in the coming weeks, and will enter preview for Microsoft 365 Premium and Pro subscribers later this year.
- Copilot Managed Runtime is a preview hosting foundation for running code safely inside a company’s Microsoft 365 environment, and it will also be available inside Code.
- For business context expansion, Fabric IQ is generally available in Chat and Cowork today, while Dynamics 365 and Power Platform data and workflow grounding will roll out in public preview over the next month. A new plugin registry is also rolling out now and will become generally available across surfaces in the coming weeks.
- For pricing and operations, Chat and apps like Word and Excel use the fixed-cost USL, while Cowork, Code, Autopilot, and frontier models use usage-based billing. Agent 365 cost management is expanding to Code and Copilot Managed Runtime, with support for Copilot Studio-built agents planned for October.

</details>

### Microsoft Fabric Blog (1)

#### [Deep dive into Power BI reporting with the new date picker slicer option (Preview)](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Deep-dive-into-Power-BI-reporting-with-the-new-date-picker/ba-p/5295674)
- 公開日時: 2026-07-16T16:00:00.000Z
- 要約: Power BIの新しいDate picker slicerオプションは、データ更新に合わせて前進する相対日付範囲を既定値として設定でき、閲覧者は必要に応じて相対範囲や任意の日付範囲へ切り替えられるプレビュー機能だ。作成者は最終日・開始日・今日を基準にした設定やオフセットを使え、公開後もその既定範囲を保てる。プレビュー期間中の作成はPower BI Desktopに限られ、公開後はPower BI serviceで表示・編集できる。
- なぜ重要か: 継続的に更新されるレポートの作成者と閲覧者の双方に関わる変更だ。記事によれば、作成者は新しいデータ到着に追随する既定の日付範囲を維持しながら手動メンテナンスを減らせ、閲覧者は公開後も相対・手動・単一日付を自分で選んで分析を続けられる。

**重要ポイント**
- 相対日付範囲は最終日・開始日・今日を基準にオフセット付きで設定でき、公開したレポートではその相対範囲が既定値になり、ダッシュボードにピン留めしても新しいデータに追随する。
- 閲覧者は単一カレンダーから相対範囲や手動範囲を選べるほか、同じ日付を2回選ぶ単一日付指定や、スライダーによる範囲の素早い調整も行える。
- 利用にはプレビュー機能の有効化が必要で、Slicer visualのFormat paneにDate pickerが現れない場合は、Power BI DesktopのPreview featuresでDate picker slicerをオンにする必要がある。
- 日付テーブルが将来日付まで含む場合は、対象メジャーにAdvanced filterで「is not blank」を設定することで、実データがある最終日を基準に相対範囲を絞り、不完全な比較期間を避けられる。

<details><summary>English summary</summary>

Power BI’s new Date picker slicer option is a preview feature that lets authors set dynamic relative date ranges that move forward as data refreshes, while viewers can switch to their own relative or manual date ranges as needed. Authors can anchor ranges to the last date, first date, or today with offsets and keep that relative range as the published default. During preview, creation is limited to Power BI Desktop, while published reports can be viewed and edited in the Power BI service.

**Why it matters:** This matters to both report authors and report viewers working with continuously refreshed reports. According to the article, authors can keep a default date range aligned with incoming data while reducing manual maintenance, and viewers can still choose relative, manual, or single-date selections after publication to continue their own analysis.

**Key points**
- Relative date ranges can be configured with offsets from the last date, first date, or today; they become the default in the published report and remain relative even when the visual is pinned to a dashboard.
- Viewers can choose relative or manual ranges from a single calendar, select a single date by choosing the same date twice, and quickly adjust the range with the slider.
- The feature requires preview enablement, and if Date picker does not appear in the slicer format pane, authors must turn on Date picker slicer in Power BI Desktop’s Preview features.
- When a date table extends into future dates, authors can apply an Advanced filter with “is not blank” on the relevant measure so the relative range is based on the last date with actual data and avoids incomplete comparison periods.

</details>
