#### [The August 17 outage, and the work ahead](https://github.blog/news-insights/company-news/the-august-17-outage-and-the-work-ahead/)
- 公開日時: 2026-08-20T18:36:11.000Z
- 要約: GitHubは8月17日に7時間47分続いた大規模障害について、トラフィック急増時にCentral USデータセンターの重要インフラがスケールできなかった容量障害だったと説明し、信頼性改善を加速するとした。障害はgithub.com、認証、Actions、API、PR、Issues、Copilotに及び、復旧後の対策として容量増強、Azure移行の加速、サービス間リトライ制御の見直しを進めている。
- なぜ重要か: GitHubに開発・出荷・運用を依存する開発者や組織にとって、今回の説明は、広範な停止を招いた原因が容量不足にあったことと、その是正策がどこに向かうのかを具体的に示す内容だ。特にCopilot利用者や大規模モノレポを抱えるチームは、復旧遅延の再発防止策やAzure移行、読み取り容量拡張の進展に直接関係する。

**重要ポイント**
- 障害の直接要因は、新たなトラフィックピーク時にCentral USの重要インフラが追随できず、容量逼迫が認証失敗や複数サービス停止に波及したことだった。Copilotの一部は復旧が遅れ、クライアント側のリトライループが回復時の負荷を増やした。
- GitHubは今回と8月6日の障害はいずれもコードや設定変更ではなく容量問題が中核だったとし、需要増に対して重要コンポーネントのスケールが間に合わなかったと認めた。背景として、月間コミット数は4月以降14億件から29億件へ増えていた。
- 対策として、既存データセンターで電力の許す限りハードウェアを増設し、300万超のCPUコア、120ペタバイトの高速ストレージ、ネットワーク容量を追加した。またAzure移行を加速し、現在はプラットフォーム負荷の約58%、Git操作の半分をAzureが処理している。
- 今後は、読み取り容量を読者数に対して線形に拡張できるアーキテクチャを大規模モノレポから段階導入する。加えて、共有依存の削減や重要系の分離、サービス間のリトライ上限・予算・可変タイムアウトの統一、低優先度のCPU・メモリアラート見直しを進める。

<details><summary>English summary</summary>

GitHub said the August 17 outage, which lasted 7 hours and 47 minutes, was a capacity failure caused when a critical Central US infrastructure component could not scale during a traffic peak. The incident affected github.com, authentication, Actions, APIs, pull requests, issues, and Copilot, and GitHub says it is accelerating reliability work through added capacity, faster Azure migration, and stricter retry controls.

</details>

### Microsoft Fabric Blog (3)

#### [The AI Semantic Layer You Probably Already Have](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/The-AI-Semantic-Layer-You-Probably-Already-Have/ba-p/5360197)
- 公開日時: 2026-08-20T19:00:00.000Z
- 要約: Fabric IQは、既存のPower BIセマンティックモデルをそのままMicrosoft 365 CopilotやAIエージェントの業務語彙の基盤として使えると説明している。記事は、レポートで長年定義してきた指標や顧客・売上の意味をAIに再利用でき、推測ではなく既存定義に基づく回答を返せる点を強調する。さらにImportやDirectQueryの現行モデルでも対応でき、AI導入のためにモデルを作り直したりDirect Lakeへ移行したりする必要はないとしている。
- なぜ重要か: 恩恵を受けるのは、既にPower BIを使っている企業のデータ部門、業務部門、経営層だ。記事によれば、AIとダッシュボードが同じセマンティックモデルを参照することで、四半期売上のような重要指標で答えが食い違う事態を避けやすくなり、BIで積み上げた信頼を保ったままAI活用を広げられる。新たな大規模構築よりも既存資産の整理が中心になるため、既存ユーザーほど影響が大きい。

**重要ポイント**
- Power BIの全レポートはセマンティックモデルの上に成り立っており、売上や顧客などの定義、テーブル間の関係、階層構造といった業務上の意味がそこで管理されている。
- Fabric IQは、その既存モデルをAIの土台として使い、自然言語の質問に対して統計的な推測ではなく企業内で合意済みの定義に基づく回答を返す位置付けだ。
- 導入にあたって既存モデルの作り直しは不要で、現在使っているImportモデルやDirectQueryモデルでも利用できる。Direct Lakeは別の利点はあるが、AI連携のための必須アップグレードではない。
- AI向けの文脈は指標定義だけに限られず、同義語、説明、承認済み回答付きのサンプル質問、さらに公開済みレポートで実際に使われている表示名まで活用できる。
- 実務上の焦点は大規模な新規データ基盤構築ではなく、信頼できるセマンティックモデルを見極め、認定・整理してFabric IQに昇格させるキュレーション作業だと記事は述べている。

<details><summary>English summary</summary>

Fabric IQ is described as letting organizations reuse existing Power BI semantic models as the business vocabulary for Microsoft 365 Copilot and AI agents. The article argues that this grounds AI answers in established metric definitions instead of guesses, and that current Import and DirectQuery models can be used without rebuilding models or moving to Direct Lake.

</details>

#### [Power BI August 2026 Feature Summary](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Power-BI-August-2026-Feature-Summary/ba-p/5348434)
- 公開日時: 2026-08-20T17:09:15.000Z
- 要約: Power BIの2026年8月版では、レポート、モデリング、データ接続、モバイル、埋め込み分析、開発者体験にまたがる更新が入り、一般提供機能とプレビュー機能が混在して追加された。レポートではFluent 2ベーステーマ導入や日付ピッカー強化が進み、Power BI Serviceではセマンティックモデル更新の選択肢が増え、作成と運用の両面に手が入った。
- なぜ重要か: 今回の更新は、Fabric Appの閲覧者や運用者、レポート利用者、モバイル利用者に広く関係する。権限はBuildからRead中心へ寄せられ、セマンティックモデル更新も必要な単位だけ選びやすくなる。さらにレポート上でのコメント連携と、モバイルからのExcel出力が加わり、共有と利用の流れが広がる。

**重要ポイント**
- Power BI Desktopの旧ファイルピッカーは4月に非推奨化され、10月以降は2026年3月以前のDesktopを使うユーザーがOne DriveとSharePointへの保存・共有を行えなくなる。
- 9月上旬には、データアプリテンプレートで作成したFabric Appの利用者は基盤セマンティックモデルにBuild権限ではなくRead権限でアクセスできるようになり、作成者には引き続きBuild権限が必要となる。
- レポート機能では、Modern visual defaultsとテーマ書式設定ペイン、Slicer向けDate pickerが一般提供となり、新規レポートの既定はFluent 2ベーステーマになり、Date pickerには単一日付を1件だけ選ぶ設定が加わった。
- Power BI Serviceのセマンティックモデル更新は、スキーマとデータの両方、スキーマのみ、データのみの3系統に分かれ、さらにテーブル単位でも更新を実行できるようになった。
- Direct Lake関連では、Webモデリングで個別テーブルをImportへ変換する機能と計算列がプレビューとして追加され、Import変換機能は今後数週間で順次ロールアウトされる。

<details><summary>English summary</summary>

Power BI's August 2026 release adds updates across reporting, modeling, data connectivity, mobile, embedded analytics, and developer workflows, combining GA enhancements with new preview capabilities. Reporting gains Fluent 2-based defaults and stronger date picker options, while Power BI Service adds more granular semantic model refresh choices that improve both authoring and maintenance.

</details>

#### [Edit your Power BI projects anywhere and reload them instantly in Power BI Desktop (Preview)](https://community.fabric.microsoft.com/t5/Power-BI-Updates-Blog/Edit-your-Power-BI-projects-anywhere-and-reload-them-instantly/ba-p/5359136)
- 公開日時: 2026-08-18T17:00:00.000Z
- 要約: Power BI Desktopは、PBIP（Power BI Projects）ファイルに外部ツールやエディター、自動処理から加えた変更を自動検知し、再起動なしで読み込めるようになった。変更がディスク上で発生すると最新プロジェクトの再読み込みを促し、Apply external changesで即時反映できる。あわせてPBIPプロジェクト向けのOpen in VS Codeも追加され、Visual Studio Codeでプロジェクトフォルダーを開いて編集しやすくなった。
- なぜ重要か: PBIPを使ってソース管理や自動化を含む開発ワークフローを回しているPower BI利用者にとって、外部編集結果をPower BI Desktopへすぐ反映できる点が重要だ。コードエディター、外部ツール、自動プロセスとの往復時にアプリ再起動が不要になり、Desktopを開いたままレポートやセマンティックモデルのファイルを継続編集しやすくなる。

**重要ポイント**
- PBIPファイルへの外部変更は、Power BI Desktopの再起動を待たずに自動検知される。
- PBIPファイルがディスク上で更新されると、Power BI Desktopは最新バージョンの再読み込みを促し、Apply external changesで更新内容を取り込める。
- Power BI DesktopにはPBIPプロジェクト向けのOpen in VS Codeが追加され、Visual Studio Codeをプロジェクトフォルダー込みのワークスペースとして直接起動できる。
- 想定利用例として、Visual Studio Codeでの編集、スクリプトや自動化による更新、PBIP成果物を変更するAI支援開発ツールとの併用が挙げられている。

<details><summary>English summary</summary>

Power BI Desktop now automatically detects external changes to PBIP files and lets users reload them without restarting the app. When project files change on disk, Desktop prompts for a reload via Apply external changes. It also adds an Open in VS Code option for PBIP projects, making it easier to edit project folders directly in Visual Studio Code.

</details>
