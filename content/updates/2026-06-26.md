#### [Evaluating performance and efficiency of the GitHub Copilot agentic harness across models and tasks](https://github.blog/ai-and-ml/github-copilot/evaluating-performance-and-efficiency-of-the-github-copilot-agentic-harness-across-models-and-tasks/)
- 公開日時: 2026-06-25T22:59:45.000Z
- 要約: GitHub Copilotのagentic harnessについて、GitHubは複数ベンチマークでモデルベンダー製ハーネスと同等のタスク達成率を保ちつつ、多くの構成でより少ないトークン消費を示したと報告した。比較対象はClaude CodeとCodex CLIで、SWE-bench群やTerminalBenchなどの公開・社内ベンチマークを同一条件に正規化して評価している。さらに1つのハーネスで20超のモデル群とBYOK/ローカルモデルに対応し、タスクごとに品質とコストの選択肢を持てる点を強調した。
- なぜ重要か: この内容はGitHub Copilot CLI、Copilot app、Copilot code reviewを使う開発者に直接関係する。共通ハーネスの改善が各体験に横断的に効き、GitHubの説明では、単一モデルに縛られずにタスクごとに最適なモデルを選びながら、同等のタスク完了率でトークンコストを抑えられる可能性があるためだ。

**重要ポイント**
- 評価対象はClaude Sonnet 4.6、Claude Opus 4.7、GPT‑5.4、GPT‑5.5の4モデルで、SWE-bench Verified、SWE-bench Pro、SkillsBench、TerminalBench、Win-Hillの一部結果を示している。SWE-bench Verifiedは500件の人手検証済みバグ修正タスクと明記されている。
- 固定したモデルとタスクで比較すると、Copilotハーネスは他社ハーネスと同等の解決率を維持しながら、多くの設定でトークン消費が低いという。TerminalBench 2.0では各エージェントとモデルの組み合わせを少なくとも5回実行し、差の多くは実行ごとのばらつきの範囲内だと説明している。
- モデル選択では、GPT、Claude、Gemini、MAIの20超のフロンティアモデルに加え、オープンソースやローカルモデルのBYOKにも対応する。Auto model selectionでタスク意図とモデル健全性を見て効率を最適化し、Rubber Duckでは異なるモデル系列間の相互批評を使う。
- 方法論では、すべての実行に2時間のタイムアウトを設定し、非対話の単一ターンでweb-toolsを無効化した。全ベンチマークで同じコンテキストウィンドウ、同じプロンプト上限、reasoning effortをmediumにそろえ、指標はpass@1で報告している。

<details><summary>English summary</summary>

GitHub says the GitHub Copilot agentic harness matches native vendor harnesses on task completion across several benchmarks while using fewer tokens in many configurations. It compares Copilot CLI with Claude Code and Codex CLI under normalized conditions across public and internal benchmarks such as SWE-bench and TerminalBench. The same harness also supports more than 20 models plus BYOK and local models, giving developers flexibility on quality and cost per task.
