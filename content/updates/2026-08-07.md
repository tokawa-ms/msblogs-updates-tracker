#### [A guide to slash commands in the GitHub Copilot app](https://github.blog/ai-and-ml/github-copilot/a-guide-to-slash-commands-in-the-github-copilot-app/)
- 公開日時: 2026-08-06T19:49:34.000Z
- 要約: GitHub Copilot appでは、チャット入力欄で使うスラッシュコマンドを中心に、計画立案から実装、批判的レビュー、可視化、複数タスクの調整までを進める使い方が整理された。記事は /plan、/autopilot、/rubber-duck、/create-canvas、/orchestrate などの役割を具体例付きで示し、CLI向けコマンドとは異なり、アプリのマルチセッション前提のワークフローに合わせた操作だと説明している。
- なぜ重要か: GitHub Copilot app を日常的に使う開発者にとって重要なのは、単なるチャット応答ではなく、計画、実装、批評、可視化、並列調整といった作業を会話入力から直接呼び出せる点だ。記事は、オプションを探して集中を切らさずに必要なワークフローへ移れること、そしてアプリ特有のマルチセッション運用に合わせて使い分けられることを示している。

**重要ポイント**
- スラッシュコマンドは GitHub Copilot app のチャット入力欄に / を打って使うテキストショートカットで、オートコンプリートから現在の文脈で使えるコマンドを選べる。
- CLIと違い、アプリ版はプロジェクト文脈を自動管理するため /add-dir や /cwd は不要で、/clear や /model など一部共通コマンドを除き、セッション管理やエージェント制御に寄った設計になっている。
- /plan は実装前の分解や課題洗い出しに使い、セッションを Plan mode に切り替える。/autopilot は実装作業を進めるためのコマンドで、セッションを Autopilot mode に切り替える。
- /rubber-duck は別モデルで独立レビューを行い、見落としや前提の甘さを探す。/create-canvas は会話から対話型UIを作れ、/orchestrate は複数リポジトリや並行タスクの調整に使える。

In the GitHub Copilot app, slash commands are presented as a workflow layer that helps developers move from planning to implementation, critique, visualization, and multi-task coordination from the chat composer. The article explains commands such as /plan, /autopilot, /rubber-duck, /create-canvas, and /orchestrate with examples, and contrasts them with CLI commands by emphasizing the app’s multi-session workflow.

#### [How we took malware advisories beyond npm](https://github.blog/security/supply-chain-security/how-we-took-malware-advisories-beyond-npm/)
- 公開日時: 2026-08-06T16:51:12.000Z
- 要約: GitHub Advisory DatabaseはOpenSSFのmalicious-packagesリポジトリからマルウェア報告を取り込み、Dependabotのマルウェアアラート対象を、従来のnpm中心の経路から8つの主要パッケージエコシステムへ広げた。新しいOpenSSF importerはOSVレコードを検証し、GitHub由来のghsa-malwareを除外して重複取り込みを防ぐ。アラートはリポジトリ、組織、またはエンタープライズ設定でのオプトイン制で、有効化した時点から既存アドバイザリもバックフィルされる。
- なぜ重要か: 影響を受けるのは、npm以外も含めてDependabotやGitHubで依存関係を管理する開発者や保守者だ。悪意あるパッケージが資格情報を即座に盗み得る前提で、レビュー待ちより迅速な自動公開とアラートを優先する設計になっており、広いエコシステムで早期通知を受けられる。一方で、この通知を使うには利用者側で明示的に有効化する必要がある。

**重要ポイント**
- OpenSSFのmalicious-packagesリポジトリは2023年に立ち上がり、OSV形式で1万5000件超の報告を持つ。データ源にはコミュニティ投稿だけでなく、typosquatやdependency confusion、アカウント乗っ取り、悪意あるプリビルドバイナリなどの自動検出も含まれる。
- 新しいOpenSSF importerは全OSVレコードをスキーマ検証し、必要な項目や型、形式を満たさない記録は拒否してログ化する。さらに、誤報として撤回されたアドバイザリを収める osv/withdrawn フォルダの存在を前提に、後から取り下げられるケースにも対応する。
- 重複取り込み対策として、OSVのorigin metadataでGitHub起点のghsa-malwareをfeed entry作成前に除外する。実データ検証では、毎月流入する新しいnpm報告の半数超が自社アドバイザリ由来で、往復データとしてスキップされた。
- 上流データの異常に備え、1回の取り込みで作成できるアドバイザリ数の上限、上流コミットまで追跡できるprovenance、バッチ単位で一括ロールバックできる仕組みの3層防御を実装した。
- 利用面では、悪意ある依存関係の検知が大半のパッケージエコシステムに広がる一方、マルウェアアラートはオプトイン制だ。リポジトリ、組織、またはエンタープライズのセキュリティ設定で有効化すると、その時点から既存アドバイザリに対するバックフィルも実行される。

<details><summary>English summary</summary>

GitHub has expanded the GitHub Advisory Database and Dependabot malware alerts from an npm-only path to eight major package ecosystems by ingesting OpenSSF malicious-packages data. The new OpenSSF importer validates OSV records and skips GitHub-originated ghsa-malware entries to avoid duplicate loops. Alerts are opt-in at the repository, organization, or enterprise level, and enabling them backfills existing advisories.

</details>
